### 前節（0-3）の確認問題の解答

前節の最後に提示した3つの問いの解答を確認します。問3がそのまま本節（命令実行サイクルとデータパス）の導入になります。

1. **全加算器と2の補数加減算器のトレース（$6 - 3$）：**
    $a = \texttt{0110}_2$（6）、$b = \texttt{0011}_2$（3）、減算制御信号 `sub = 1` とします。

    * **(a) XORゲート通過後の値と最下位桁上げ入力：**
        `sub = 1` なので、$b$ の全ビットが反転されて $b \oplus \text{sub} = \mathbf{\texttt{1100}_2}$ となります。また、最下位ビットへ入る桁上げ入力は $c_{\text{in}}[0] = \text{sub} = \mathbf{1}$ です。

    * **(b) 加算器の計算結果の確認：**
        4ビット加算器が計算する和は次の通りです。

        $$\texttt{0110}_2 + \texttt{1100}_2 + \texttt{0001}_2 = \texttt{10011}_2$$

        5ビット目の桁上がり `1` を捨てた下位4ビットは **$\texttt{0011}_2$（10進数で $3$）** となり、$6 - 3 = 3$ の正しい結果と一致します。

2. **クリティカルパスと動作周波数の上限：**

    * **(a) 分割前の動作周波数上限（$T_{\text{crit}} = 12.5\text{ ns}$）：**

        $$f \le \frac{1}{12.5 \times 10^{-9}\text{ s}} = 80 \times 10^6\text{ Hz} = \mathbf{80\text{ MHz}}$$

    * **(b) 2区間に分割後の動作周波数上限：**
        前半 $6.0\text{ ns}$、後半 $6.5\text{ ns}$ のうち、遅延の大きい後半 $6.5\text{ ns}$ が新しいクリティカルパスになります。したがって上限周波数は、

        $$f \le \frac{1}{6.5 \times 10^{-9}\text{ s}} \approx 153.85 \times 10^6\text{ Hz} \approx \mathbf{153.8\text{ MHz}}$$

        まで引き上げられます（レジスタ自体のセットアップ遅延等を無視した理想値）。

3. **部品を並べてCPUにしたときのクリティカルパス（本節への接続）：**
    加算器・マルチプレクサ・レジスタ・メモリを繋いでCPUを組み立てたとき、「命令を読み出す → レジスタを読む → アドレスを計算する → データメモリを読み出す → レジスタへ書き戻す」という**全5段階を直列に通るロード命令（`lw`）**が最も遅い経路（クリティカルパス）になります。

## 0-4. 命令実行サイクルとシングル／マルチサイクルプロセッサ

### 1. 動機（Why）：論理ゲートとレジスタをどう繋げば「プログラムを実行するCPU」になるのか

前節（0-3節）までで、ビット列の表現、メモリの配置、そして加算器・マルチプレクサ（MUX）・レジスタというデジタル回路の基本部品が揃いました。では、これらをどう組み合わせれば、メモリ上に置かれた機械語命令を1つずつ解釈して実行する**プロセッサ（CPU）**になるのでしょうか。

CPUの設計を初めて学ぶとき、何百種類もある現代の機械語命令を一度に追いかけようとすると全体像が見えなくなります。しかし実は、コンピュータがプログラムを実行するうえで本質的に必要な命令の種類は、次の4系統に絞ることができます。

1. **演算命令（`add`, `addi`）：** レジスタ同士、あるいはレジスタと定数（即値）を足し引きする。
2. **ロード命令（`lw`）：** メモリからデータを読み出してレジスタへ入れる。
3. **ストア命令（`sw`）：** レジスタのデータをメモリへ書き込む。
4. **条件分岐命令（`beq`）：** 2つのレジスタが等しければ、別の場所の命令へジャンプする。

本節では、命令の構造が整理されていて仕組みを見通しやすい **RISC-V（32ビット基本整数命令セット：RV32I）** のこの最小5命令を題材に、命令が実行される **5つの基本ステップ（IF → ID → EX → MEM → WB）** と回路の繋がり（**データパス**）を組み立てます。さらに、1命令を1クロックで終える**シングルサイクル方式**と、ステップごとにクロックを分ける**マルチサイクル方式**を性能式 $\text{Performance} = f \times \text{IPC}$ で比較し、「なぜ周波数を上げるだけではCPUは速くならないのか」を確認します。

---

### 2. 具体例と動作イメージ（Toy Model）

データパス全体を見る前に、1本のロード命令 `lw x5, 8(x7)` がCPUの内部を旅する様子を手計算で追ってみます。

#### 実験A：ロード命令 `lw x5, 8(x7)` の5ステップを追う

RISC-Vのレジスタは `x0`〜`x31` の32本（各32ビット）あり、次に実行する命令のメモリアドレスを保持する専用レジスタを**プログラムカウンタ（PC）**と呼びます。今、`PC = 0x1000`、レジスタ `x7 = 0x2000`、そしてデータメモリの `0x2008` 番地に数値 `42` が入っているとします。

アドレス `0x1000` に置かれた命令 `lw x5, 8(x7)`（「`x7 + 8` 番地のメモリから4バイトを読み、レジスタ `x5` へ入れよ」）は、CPU内部を次の5段階で通り抜けます。

1. **IF（Instruction Fetch：命令フェッチ）：**
    `PC` が指す `0x1000` 番地から、32ビット（4バイト）の機械語命令 `lw x5, 8(x7)` を命令メモリから読み出します。同時に、次の命令へ進むために `PC + 4`（`0x1004`）を用意します。
2. **ID（Instruction Decode：命令デコードとレジスタ読出し）：**
    読み出した32ビットのビット列を分解し、「これはロード命令（`lw`）で、基準レジスタは `x7`、書き込み先は `x5`、オフセット即値は `8` だ」と解釈します。同時にレジスタファイルから `x7` の値 `0x2000` を読み出し、12ビットの即値 `8` を32ビットへ符号拡張（0-1節）します。
3. **EX（Execution：演算実行）：**
    **ALU（算術論理演算装置）**を使って、基準アドレス `0x2000` とオフセット `8` を加算し、アクセス先のメモリアドレス `0x2008` を計算します。
4. **MEM（Memory Access：メモリアクセス）：**
    計算したアドレス `0x2008` をデータメモリへ渡し、そこに格納されている値 `42` を読み出します。
5. **WB（Write Back：書き戻し）：**
    読み出した値 `42` を、書き込み先レジスタ `x5` へ書き込みます。同時に `PC` を `0x1004` へ更新し、1命令が完了します。

ここで重要なのは、他の命令はこの5ステップのうち**不要なステップを素通りする**点です。たとえば加算命令 `add x3, x1, x2` は、EXで `x1 + x2` を計算したらMEM（データメモリ）を使わずにそのままWBで `x3` へ書き戻します。ストア命令 `sw x3, 8(x7)` はMEMでメモリへ書き込んだら終わりなのでWBを使いません。分岐命令 `beq x1, x2, offset` はEXで `x1 == x2` を判定して `PC` を更新するだけで、MEMもWBも使いません。

### 3. 構造・アルゴリズム・実装（What）

#### (1) プロセッサを構成する主要コンポーネントとデータパス

実験Aの5ステップを実現するために、前節の基本部品を繋ぎ合わせた回路を**データパス（Datapath）**と呼びます。最小のRISC-Vプロセッサ（`add`/`addi`/`lw`/`sw`/`beq` 対応）は、次の6つの部品と数個のマルチプレクサ（MUX）だけで構成できます（図0-4-1）。

* **プログラムカウンタ（PC）：** 32ビットのレジスタ。クロックの立ち上がりごとに次の命令アドレス（通常は `PC + 4`、分岐成立時は `PC + オフセット`）へ更新されます。
* **命令メモリ（IMEM）：** `PC` の値を受け取り、32ビットの機械語命令を出力します。
* **レジスタファイル（Register File）：** 32本の32ビットレジスタ（`x0`〜`x31`）を収めた高速記憶装置です。`add rd, rs1, rs2` のように1命令で2つのソースレジスタを同時に読むため、**2ポート読み出し・1ポート書き込み**の構造を持ちます。
* **即値生成器（ImmGen）：** 命令のビット列（32ビット）から即値フィールドを切り出し、32ビットの符号拡張値へ整える組合せ回路です。
* **ALU（Arithmetic Logic Unit）：** 0-3節の加減算器や論理ゲート・比較器をまとめた演算装置です。`add`/`addi` では数値演算、`lw`/`sw` ではメモリアドレス計算、`beq` では等価判定（`rs1 == rs2`）を担います。
* **データメモリ（DMEM）：** `lw` で読み出し、`sw` で書き込みを行う主記憶です。

命令の種類（命令の下位7ビット `opcode`）に応じて信号の経路を切り替えるのが、図中の **3つのMUX** と書き込み許可信号（イネーブル）です。

| 制御ポイント | 選択の切り替え内容 |
| :--- | :--- |
| **ALU第2入力のMUX** | `add` ならレジスタ値 `rs2` を選択。`addi`/`lw`/`sw` なら即値 `imm` を選択。 |
| **書き戻しデータのMUX** | `lw` ならデータメモリからの読出し値を選択。`add`/`addi` ならALUの演算結果を選択。 |
| **次PC選択のMUX** | `beq` かつ `rs1 == rs2`（分岐成立）なら分岐先 `PC + imm` を選択。それ以外は `PC + 4` を選択。 |
| **書き込みイネーブル** | レジスタ書込みは `add`/`addi`/`lw` のみ許可。データメモリ書込みは `sw` のみ許可。 |

#### (2) プロセッサの性能式：$\text{Performance} = f \times \text{IPC}$

異なるCPU設計の速さを正しく比較するには、「クロック周波数が高い方が速い」という素朴な見方では不十分です。1秒あたりに何個の機械語命令を完了できるか（スループット）は、次の式で決まります。

$$\text{Performance} = f \times \text{IPC} = \frac{f}{\text{CPI}}$$

* **$f$（クロック周波数）：** 1秒あたりのクロック回数（単位：$\text{Hz}$）。クリティカルパス遅延 $T_{\text{crit}}$ の逆数で上限が決まります。
* **$\text{IPC}$（Instructions Per Cycle）：** 1クロックあたりに完了する命令数の平均値です。
* **$\text{CPI}$（Cycles Per Instruction）：** 1命令を完了するのにかかる平均クロック数であり、$\text{CPI} = 1 / \text{IPC}$ の逆数関係にあります。

この式は、**「クロック周波数 $f$ を2倍にしても、1命令にかかるサイクル数（CPI）が2倍になれば性能はまったく変わらない」**という重要な事実を示しています。

#### (3) シングルサイクル方式 vs マルチサイクル方式の数値比較

具体的な遅延時間を置いて、シングルサイクル方式とマルチサイクル方式を比べてみます。図0-4-1の各ステージにかかる物理遅延が次の通りだと仮定します（レジスタ自体のオーバーヘッドは無視した理想モデル）。

* **IF（命令読出し）：** $5\text{ ns}$
* **ID（デコード・レジスタ読出し）：** $4\text{ ns}$
* **EX（ALU演算）：** $4\text{ ns}$
* **MEM（データメモリ読出し／書込み）：** $5\text{ ns}$
* **WB（レジスタ書戻し）：** $2\text{ ns}$

**方式1：シングルサイクルプロセッサ（1命令＝1サイクル）**
すべての命令を1クロックサイクルで完了させるため、クロック周期 $T_{\text{clk}}$ は全5ステージを使う最も遅い `lw` 命令の合計時間に合わせる必要があります。

$$T_{\text{clk}} = 5 + 4 + 4 + 5 + 2 = \mathbf{20\text{ ns}}$$

* 動作周波数：$f = \frac{1}{20 \times 10^{-9}\text{ s}} = \mathbf{50\text{ MHz}}$
* 1サイクルあたり完了命令数：$\text{IPC} = \mathbf{1.0}$
* 性能：$\text{Performance} = 50\text{ MHz} \times 1.0 = \mathbf{50\text{ MIPS}}$（毎秒5,000万命令）

**方式2：5段固定マルチサイクルプロセッサ（1命令＝5サイクル）**
0-3節で学んだ「クリティカルパスの途中にレジスタを挿入する」発想を適用し、IF・ID・EX・MEM・WBの各ステージ間に中間レジスタを置いて、1サイクルに1ステージずつ進める方式です。クロック周期は**最も遅い単一ステージ（IFとMEMの $5\text{ ns}$）**に合わせれば済みます。

$$T_{\text{clk}} = \max(5, 4, 4, 5, 2) = \mathbf{5\text{ ns}}$$

* 動作周波数：$f = \frac{1}{5 \times 10^{-9}\text{ s}} = \mathbf{200\text{ MHz}}$（シングルサイクルの**4倍**に向上）
* 1サイクルあたり完了命令数：1命令に5サイクルかかるため $\text{IPC} = \frac{1}{5} = \mathbf{0.2}$
* 性能：$\text{Performance} = 200\text{ MHz} \times 0.2 = \mathbf{40\text{ MIPS}}$（毎秒4,000万命令）

周波数が $50\text{ MHz}$ から $200\text{ MHz}$ へ4倍に上がったにもかかわらず、**性能は 50 MIPS から 40 MIPS へむしろ低下**しました（図0-4-2）。理由は2つあります。第1に、各ステージの遅延が均等でないため（WBは $2\text{ ns}$ しかないのに $5\text{ ns}$ 待たされる）、1命令あたりの実時間が $20\text{ ns}$ から $5\text{ ns} \times 5 = 25\text{ ns}$ へ伸びたためです。第2に、1つの命令がWBを終えるまで次の命令を始めないため、IF〜MEMの各回路が5サイクル中4サイクルは遊休状態になってしまうためです。

> **【コラム：常に `0` を返すレジスタ `x0` が命令セットと回路を簡潔にする仕組み】**
>
> RISC-Vの32本の汎用レジスタのうち、先頭の **`x0`（別名 `zero`）は値が常に `0` に固定されており、何を書き込もうとしても無視されます**。貴重なレジスタを1本つぶしてまで `0` 専用にするのはもったいなく見えますが、これによって命令セット（ISA）とハードウェア回路の双方が大幅に簡潔になります。
>
> * **専用命令を減らせる：** 別のレジスタへ値をコピーする `mv rd, rs` は `addi rd, rs, 0` で代用でき、定数を読み込む `li rd, imm` は `addi rd, x0, imm` で表せます。さらに何もしない命令 `nop` も専用の機械語を用意せず `addi x0, x0, 0` として定義できます。
> * **書き込み制御回路が単純になる：** データパスのWBステージでレジスタへの書き込みが不要な命令（`sw` や `beq` など）を処理するとき、書き込み先番号を強制的に `rd = 0`（`x0`）に差し替えるだけで、余計な書き込み抑止の分岐を設けずに安全に結果を捨てられます。
>
> 32本のうち1本を定数 `0` に割り当てるという小さな設計上の決断が、命令の種類の削減とデコード回路の簡略化という大きな実益を生んでいます。

### 4. 限界と補正（Critique & Adaptation）

3-(3)の数値比較で見えた通り、シングルサイクル方式にも固定マルチサイクル方式にも明確な限界があります。

#### (1) シングルサイクル方式の限界と、マルチサイクルにおける状態遷移最適化

シングルサイクル方式の最大の弱点は、**めったに出現しない最も遅い命令（`lw`）の遅延に、頻繁に出現する軽い命令（`add` や `beq`）のクロック周期まで引きずられる**ことです。また、1クロックの間に命令メモリとデータメモリの両方を同時に参照し、さらに `PC + 4` 用・分岐先計算用・ALU本体の加算器をすべて別々に用意しなければならないため、回路規模も大きくなります。

これに対するマルチサイクル方式側での最初の補正が、**不要なステージを省略する状態遷移最適化（可変サイクル化）**です（図0-4-3）。

* **`beq`：** `IF → ID → EX → IF`（**3サイクル**）
* **`add`, `addi`：** `IF → ID → EX → WB → IF`（**4サイクル**）
* **`sw`：** `IF → ID → EX → MEM → IF`（**4サイクル**）
* **`lw`：** `IF → ID → EX → MEM → WB → IF`（**5サイクル**）

たとえば実行される命令の割合が `beq: 10%`、`lw: 10%`、`add/addi/sw: 80%` だとすると、平均サイクル数（CPI）は

$$\text{CPI} = 0.10 \times 3 + 0.10 \times 5 + 0.80 \times 4 = 0.3 + 0.5 + 3.2 = \mathbf{4.0 \text{ サイクル}}$$

となり、$\text{IPC} = 1 / 4.0 = 0.25$ へ改善します。先ほどの $200\text{ MHz}$ の例では $\text{Performance} = 200 \times 0.25 = \mathbf{50\text{ MIPS}}$ となり、ようやくシングルサイクルと並びます。

#### (2) マルチサイクル方式の本質的な限界（次節パイプラインへの動機）

状態遷移を最適化してさえ、マルチサイクル方式の $\text{IPC}$ は $0.25$ 程度（4サイクルに1命令）に留まり、シングルサイクル方式を大きく超えるスループットは得られません。根本原因は、**「1つ目の命令がMEMやWBを進んでいる間、すでに仕事が終わって空いているIF・ID・EXの回路を遊ばせている」**ことにあります。

もし、工場の流れ作業（ベルトコンベア）のように、1つ目の命令がIDへ進んだ瞬間に2つ目の命令をIFへ投入し、全5ステージを毎サイクル同時に稼働させられれば、クロック周波数をマルチサイクル並みの **$200\text{ MHz}$** に保ったまま、理想的には **$\text{IPC} \approx 1.0$**（$\text{Performance} \approx 200\text{ MIPS}$、シングルサイクルの**4倍**）を達成できます。この発想こそが、次節（0-5節）で導入する**パイプライン処理**です。

### 5. 接続と展望（Bridge）：本節の内容が後半のどの部に繋がるか

1. **次節（0-5節：5段パイプラインと構造・制御ハザード）：**
    本節で組み立てた5ステージのデータパス（IF・ID・EX・MEM・WB）をそのまま使い、複数命令をステージ単位で重ねて並列実行する**5段パイプライン**へ発展させます。
2. **第1部（1-1・1-2節：ISAの設計思想と機械語命令）：**
    本節のRISC-V（固定長32ビット・ロード／ストアアーキテクチャ）と、x86-64（可変長・メモリ直接演算ありのCISC）の設計思想の違いを対比します。
3. **第3部（3-3・3-6節：コンテクストスイッチとトラップ処理）：**
    本節で登場した `PC` と汎用レジスタ `x0`〜`x31` の組こそが、OSがプロセスを切り替えるときに丸ごと退避・復元する「CPUの状態（コンテクスト）」の実体になります。

### 理解度チェック（次節へ進む前の確認）

本節のデータパスと性能式 $\text{Performance} = f \times \text{IPC}$ を具体的な数値で確認し、次節（0-5節）へ繋ぐ問いを置きます。

> **【確認の問い】**
>
> 1. **（各命令が通るステージの整理）**
>     本節のRISC-V最小5命令（`add`, `addi`, `lw`, `sw`, `beq`）のうち、次の条件に当てはまる命令をすべて挙げてください。
>
>     * (a) 4番目のステージ **MEM（データメモリ）** を使用する命令。
>     * (b) 5番目のステージ **WB（レジスタファイルへの書き戻し）** を使用する命令。
>
> 2. **（性能式 $\text{Performance} = f \times \text{IPC}$ の計算）**
>     あるプロセッサの各ステージの遅延が IF: $4\text{ ns}$、ID: $2\text{ ns}$、EX: $4\text{ ns}$、MEM: $6\text{ ns}$、WB: $4\text{ ns}$ であるとします（レジスタ遅延は無視）。
>
>     * (a) シングルサイクル方式でのクロック周期、動作周波数 $f$（MHz）、および性能（MIPS）を求めてください。
>     * (b) 5段固定マルチサイクル方式（全命令5サイクル）でのクロック周期、動作周波数 $f$（MHz、小数第1位まで）、$\text{IPC}$、および性能（MIPS、小数第1位まで）を求め、(a) と比較してください。
>
> 3. **（次節への伏線：流れ作業にしたときに何がぶつかるか）**
>     本節の最後で、IF〜WBの5ステージを流れ作業（パイプライン）で重ねて動かせば、高い周波数と $\text{IPC} \approx 1.0$ を両立できる見通しを立てました。では、命令1の直後に命令2をすぐ流し込んだとき、もし「命令1が計算した結果のレジスタを命令2がすぐ読む」場合や、「命令1が条件分岐（`beq`）でジャンプするかどうかまだ決まっていない」場合には、どのような問題が生じるでしょうか。
