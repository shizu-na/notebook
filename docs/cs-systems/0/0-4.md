### 前節（0-3）の確認問題の解答

前節の最後に提示した3つの問いの解答を確認します。

1. **4ビット桁上げ先見加算器（CLA）の手計算検証（$a = \texttt{0111}_2,\ b = \texttt{0101}_2,\ c_0 = 0$）：**

    * **(a) 各ビットの生成信号 $g_i = a_i \land b_i$ と伝播信号 $p_i = a_i \oplus b_i$：**
        下位ビットから順に $(a_0, b_0) = (1, 1)$、$(a_1, b_1) = (1, 0)$、$(a_2, b_2) = (1, 1)$、$(a_3, b_3) = (0, 0)$ であるため、各信号は次の通りです。

        * $i = 0$：$g_0 = 1 \land 1 = \mathbf{1}$、$p_0 = 1 \oplus 1 = \mathbf{0}$
        * $i = 1$：$g_1 = 1 \land 0 = \mathbf{0}$、$p_1 = 1 \oplus 0 = \mathbf{1}$
        * $i = 2$：$g_2 = 1 \land 1 = \mathbf{1}$、$p_2 = 1 \oplus 1 = \mathbf{0}$
        * $i = 3$：$g_3 = 0 \land 0 = \mathbf{0}$、$p_3 = 0 \oplus 0 = \mathbf{0}$

    * **(b) 先見公式による $c_2$ の検証：**
        先見公式へ代入すると次の結果になります。

        $$c_2 = g_1 \lor (p_1 \land g_0) \lor (p_1 \land p_0 \land c_0) = 0 \lor (1 \land 1) \lor (1 \land 0 \land 0) = \mathbf{1}$$

        リップルキャリー方式でも、$c_1 = g_0 \lor (p_0 \land c_0) = 1$ を経由して $c_2 = g_1 \lor (p_1 \land c_1) = 0 \lor (1 \land 1) = \mathbf{1}$ となり一致します（検算：$7 + 5 = 12 = \texttt{1100}_2$）。$c_2$ の式に現れる $g_0, g_1, p_0, p_1, c_0$ はすべて最初の入力 $(a, b, c_0)$ だけから並列に決まるため、下位からの $c_1$ の伝播を待たずに一気に確定できます。

2. **レジスタ遅延込みのスラック検証とパイプライン分割の限界：**

    * **(a) 目標周波数 $100\text{ MHz}$（$T_{\text{target}} = 10.0\text{ ns}$）でのスラック：**
        クリティカルパス遅延が $T_{\text{crit}} = 10.0 + 0.5 = 10.5\text{ ns}$ であるため、スラックは次の値になります。

        $$\text{Slack} = T_{\text{target}} - T_{\text{crit}} = 10.0 - 10.5 = \mathbf{-0.5\text{ ns}}$$

        スラックが負になっているため、次のクロック立ち上がりまでに信号が次段レジスタのセットアップ時間を満たせず、**正常に動作しません**。

    * **(b) 10等分したときのクロック周期・上限周波数と「10倍にならない」理由：**
        各段の組合せ遅延 $1.0\text{ ns}$ にレジスタオーバーヘッド $0.5\text{ ns}$ が毎回加算されるため、最小クロック周期と上限周波数は次の通りになります。

        $$T_{\text{crit}} = 1.0 + 0.5 = \mathbf{1.5\text{ ns}}, \qquad f \le \frac{1}{1.5 \times 10^{-9}\text{ s}} \approx \mathbf{666.7\text{ MHz}}$$

        分割前（$10.5\text{ ns} \approx 95.2\text{ MHz}$）と比べるとちょうど **$7.0$ 倍**（$= 10.5 / 1.5$）にとどまります。組合せ回路の遅延は $1/10$ に縮む一方、レジスタ自身のオーバーヘッド（$t_{\text{clk-to-q}} + t_{\text{setup}} = 0.5\text{ ns}$）は分割しても減らず各段にかかるため、分割数を増やしても周波数は段数に比例して伸びません。

3. **電力の壁（$P \propto C V^2 f$ による単コア高クロック vs デュアルコア低電圧）：**

    * **(a) 消費電力の比較：**
        基準電力 $P_0 = \alpha C V^2 f$ に対する比率を計算します。

        * **案A（単コア高クロック）：** $P_A / P_0 = 1 \times (1.2)^2 \times 1.5 = 1.44 \times 1.5 = \mathbf{2.16\text{ 倍}}$ です。
        * **案B（デュアルコア低電圧）：** $P_B / P_0 = 2 \times (0.8)^2 \times 0.75 = 1.5 \times 0.64 = \mathbf{0.96\text{ 倍}}$ です。

        電圧 $V$ が2乗で消費電力に効くため、案Bは案Aの約 $44.4\%$（$4/9$）の電力、さらに基準の単コア構成よりも少ない消費電力で同じ $1.5$ 倍の理論処理能力を達成できます。

    * **(b) 単一スレッド処理における案Bの弱点：**
        並列化できない逐次処理では2コアのうち1コアしか稼働させられないため、案Bの実行速度は単コア周波数そのままの **$0.75$ 倍** に低下します（案Aの $1.5$ 倍に対して半分）。マルチコア化による電力効率の恩恵を引き出すには、ソフトウェア側で処理を並列化する必要があります。

## 0-4. 命令実行サイクルとシングル／マルチサイクルプロセッサ

### 1. 動機（Why）：論理ゲートとレジスタをどう繋げば「プログラムを実行するCPU」になるのか

前節（[0-3節](0-3.md)）までで、ビット列の表現、メモリの配置、そして加算器・マルチプレクサ（MUX）・レジスタというデジタル回路の基本部品が揃いました。では、これらをどう組み合わせれば、メモリ上に置かれた機械語命令を1つずつ解釈して実行する**プロセッサ（CPU）**になるのでしょうか。

CPUの設計を初めて学ぶとき、何百種類もある現代の機械語命令を一度に追いかけようとすると全体像が見えなくなります。しかし実は、コンピュータがプログラムを実行するうえで本質的に必要な命令の種類は、次の4系統に絞ることができます。

1. **演算命令（`add`, `addi`）：** レジスタ同士、あるいはレジスタと定数（即値）を足し引きします。
2. **ロード命令（`lw`）：** メモリからデータを読み出してレジスタへ入れます。
3. **ストア命令（`sw`）：** レジスタのデータをメモリへ書き込みます。
4. **条件分岐命令（`beq`）：** 2つのレジスタが等しければ、別の場所の命令へジャンプします。

本節では、オープン仕様で命令の構造が整理されており仕組みを見通しやすい **RISC-V（32ビット基本整数命令セット：RV32I）** のこの最小5命令を題材に、命令が実行される **5つの基本ステップ（IF → ID → EX → MEM → WB）** と回路の繋がり（**データパス**）を組み立てます。さらに、1命令を1クロックで終える**シングルサイクル方式**と、ステップごとにクロックを分ける**マルチサイクル方式**を性能式 $\text{Performance} = f \times \text{IPC}$ で比較し、「なぜ周波数を上げるだけではCPUは速くならないのか」を確認します。

---

### 2. 具体例と動作イメージ（Toy Model）

データパス全体を見る前に、1本のロード命令 `lw x5, 8(x7)` がCPUの内部を旅する様子を手計算で追ってみます。

#### 実験A：ロード命令 `lw x5, 8(x7)` の5ステップを追う

RISC-Vのレジスタは `x0`〜`x31` の32本（各32ビット）あり、次に実行する命令のメモリアドレスを保持する専用レジスタを**プログラムカウンタ（PC）**と呼びます。今、`PC = 0x1000`、レジスタ `x7 = 0x2000`、そしてデータメモリの `0x2008` 番地に数値 `42` が入っているとします。

アドレス `0x1000` に置かれた命令 `lw x5, 8(x7)`（「`x7 + 8` 番地のメモリから4バイトを読み、レジスタ `x5` へ入れよ」）は、CPU内部を次の5段階で通り抜けます。

1. **IF（Instruction Fetch：命令フェッチ）：**
    `PC` が指す `0x1000` 番地から、32ビット（4バイト）の機械語命令 `lw x5, 8(x7)` を命令メモリから読み出します。同時に、次の命令へ進むために `PC + 4`（`0x1004`）を用意します。

2. **ID（Instruction Decode：命令デコードとレジスタ読出し）：**
    読み出した32ビットのビット列を分解し、「これはロード命令（`lw`）で、基準レジスタは `x7`、書き込み先は `x5`、オフセット即値は `8` だ」と解釈します。同時にレジスタファイルから `x7` の値 `0x2000` を読み出し、命令内の12ビット即値 `8` を32ビットへ符号拡張（[0-1節](0-1.md)）します（32ビット固定長の命令の中に命令の種類やレジスタ番号も同時に収める必要があるため、即値に割り当てられる幅は12ビットになっています）。

3. **EX（Execution：演算実行）：**
    **ALU（算術論理演算装置）**を使って、基準アドレス `0x2000` とオフセット `8` を加算し、アクセス先のメモリアドレス `0x2008` を計算します。

4. **MEM（Memory Access：メモリアクセス）：**
    計算したアドレス `0x2008` をデータメモリへ渡し、そこに格納されている値 `42` を読み出します。

5. **WB（Write Back：書き戻し）：**
    読み出した値 `42` を、書き込み先レジスタ `x5` へ書き込みます。同時に `PC` を `0x1004` へ更新し、1命令が完了します。

ここで重要なのは、他の命令はこの5ステップのうち**不要なステップを素通りする**点です。たとえば加算命令 `add x3, x1, x2` は、EXで `x1 + x2` を計算したらMEM（データメモリ）を使わずにそのままWBで `x3` へ書き戻します。ストア命令 `sw x3, 8(x7)`（「`x3` の値を `x7 + 8` 番地へ書き込め」；`lw` では左が書き込み先レジスタであるのに対し、`sw` では左がメモリへ書き込む元データ側のレジスタになる点に注意します）はMEMでメモリへ書き込んだら終わりなのでWBを使いません。分岐命令 `beq x1, x2, offset` はEXで `x1 == x2` を判定して `PC` を更新するだけで、MEMもWBも使いません。

### 3. 構造・アルゴリズム・実装（What）

#### (1) プロセッサを構成する主要コンポーネントとデータパス

実験Aの5ステップを実現するために、前節の基本部品を繋ぎ合わせた回路を**データパス（Datapath）**と呼びます。最小のRISC-Vプロセッサ（`add`/`addi`/`lw`/`sw`/`beq` 対応）は、次の6つの部品と数個のマルチプレクサ（MUX）だけで構成できます（図0-4-1）。

* **プログラムカウンタ（PC）：** 32ビットのレジスタであり、クロックの立ち上がりごとに次の命令アドレス（通常は `PC + 4`、分岐成立時は `PC + オフセット`）へ更新されます。
* **命令メモリ（IMEM）：** `PC` の値を受け取り、32ビットの機械語命令を出力します。
* **レジスタファイル（Register File）：** 32本の32ビットレジスタ（`x0`〜`x31`）を収めた高速記憶装置です。`add rd, rs1, rs2` のように1命令で2つのソースレジスタを同時に読むため、データの出入り口（**ポート**）として**2ポート読み出し・1ポート書き込み**の構造を持ちます。
* **即値生成器（ImmGen）：** 命令のビット列（32ビット）から即値フィールドを切り出し、32ビットの符号拡張値へ整える組合せ回路です。
* **ALU（Arithmetic Logic Unit）：** [0-3節](0-3.md)の加減算器や論理ゲート・比較器をまとめた演算装置です。`add`/`addi` では数値演算、`lw`/`sw` ではメモリアドレス計算、`beq` では等価判定（`rs1 == rs2`）を担います。
* **データメモリ（DMEM）：** `lw` で読み出し、`sw` で書き込みを行う主記憶です。

命令の種類（命令の下位7ビット `opcode`）に応じて信号の経路を切り替えるのが、図中の **3つのMUX** と書き込み許可信号（イネーブル）です。

| 制御ポイント | 選択の切り替え内容 |
| :--- | :--- |
| **ALU第2入力のMUX** | `add`・`beq` ならレジスタ値 `rs2` を選択（`beq` では `rs1` と `rs2` の比較に使用）。`addi`/`lw`/`sw` なら即値 `imm` を選択。 |
| **書き戻しデータのMUX** | `lw` ならデータメモリからの読出し値を選択。`add`/`addi` ならALUの演算結果を選択。 |
| **次PC選択のMUX** | `beq` かつ `rs1 == rs2`（分岐成立）なら分岐先 `PC + imm` を選択。それ以外は `PC + 4` を選択。 |
| **書き込みイネーブル** | レジスタ書込み（`RegWrite`）は `add`/`addi`/`lw` のみ許可。データメモリ書込み（`MemWrite`）は `sw` のみ許可。 |

> **【コラム：なぜデータパスでは命令メモリとデータメモリが分かれているのか（フォン・ノイマン型 vs 修正ハーバード型）】**
>
> [0-1節](0-1.md)で「命令もデータもすべて同じメモリに格納される」と確認したのに、図0-4-1では「命令メモリ（IMEM）」と「データメモリ（DMEM）」が2つの別々の箱として描かれていることに疑問を感じるかもしれません。
>
> コンピュータの基本構造には、命令とデータを同じ1つの記憶空間に収める**フォン・ノイマン型（プログラム内蔵方式）**と、命令用メモリとデータ用メモリを物理的に分離する**ハーバード型**の2種類があります。汎用コンピュータの主記憶（DRAM）は、プログラム自体をデータとしてメモリへ読み込み・配置したり（実行ファイルをメモリへ展開するOS機能の**ローダ**や、ソースコードを機械語へ翻訳する**コンパイラ**）、用途に応じてメモリ容量を柔軟に配分したりできる**フォン・ノイマン型**です。
>
> 一方、CPU内部の実行効率の観点では、1サイクルの間に「命令の読み出し（IF）」と「データの読み書き（MEM）」を同時に行えた方が有利です（次節0-5のパイプラインでは毎サイクル両方が同時に発生します）。そこで現代の汎用CPUは、**主記憶とL2/L3キャッシュの層では命令とデータを同じ空間に置くフォン・ノイマン型を保ちつつ、CPUコア直結のL1キャッシュ層（[0-7節](0-7.md)）だけを「L1命令キャッシュ」と「L1データキャッシュ」に分離する**折衷構造をとっています。この構成を**修正ハーバード型（Modified Harvard Architecture）**と呼び、図0-4-1の2つのメモリ箱はこのL1層の分離を抽象化したものです。

#### (2) プロセッサの性能式：$\text{Performance} = f \times \text{IPC}$

異なるCPU設計の速さを正しく比較するには、「クロック周波数が高い方が速い」という素朴な見方では不十分です。1秒あたりに何個の機械語命令を完了できるか（スループット）は、次の式で決まります。

$$\text{Performance} = f \times \text{IPC} = \frac{f}{\text{CPI}}$$

* **$f$（クロック周波数）：** 1秒あたりのクロック回数（単位：$\text{Hz}$）。クリティカルパス遅延 $T_{\text{crit}}$ の逆数で上限が決まります。
* **$\text{IPC}$（Instructions Per Cycle）：** 1クロックあたりに完了する命令数の平均値です。
* **$\text{CPI}$（Cycles Per Instruction）：** 1命令を完了するのにかかる平均クロック数であり、$\text{CPI} = 1 / \text{IPC}$ の逆数関係にあります。

この式は、**「クロック周波数 $f$ を2倍にしても、1命令にかかるサイクル数（CPI）が2倍になれば性能はまったく変わらない」**という重要な事実を示しています。

#### (3) シングルサイクル方式 vs マルチサイクル方式の数値比較

具体的な遅延時間を置いて、シングルサイクル方式とマルチサイクル方式を比べてみます。図0-4-1の各ステージにかかる物理遅延が次の通りだと仮定します（レジスタ自体のオーバーヘッドは無視した理想モデル）。

* **IF（命令読出し）：** $5\text{ ns}$ です。
* **ID（デコード・レジスタ読出し）：** $4\text{ ns}$ です。
* **EX（ALU演算）：** $4\text{ ns}$ です。
* **MEM（データメモリ読出し／書込み）：** $5\text{ ns}$ です。
* **WB（レジスタ書戻し）：** $2\text{ ns}$ です。

**方式1：シングルサイクルプロセッサ（1命令＝1サイクル）**
すべての命令を1クロックサイクルで完了させるため、クロック周期 $T_{\text{clk}}$ は全5ステージを使う最も遅い `lw` 命令の合計時間に合わせる必要があります。

$$T_{\text{clk}} = 5 + 4 + 4 + 5 + 2 = \mathbf{20\text{ ns}}$$

* 動作周波数：$f = \frac{1}{20 \times 10^{-9}\text{ s}} = \mathbf{50\text{ MHz}}$ です。
* 1サイクルあたり完了命令数：$\text{IPC} = \mathbf{1.0}$ です。
* 性能：$\text{Performance} = 50\text{ MHz} \times 1.0 = \mathbf{50\text{ MIPS}}$（**MIPS**：Million Instructions Per Second、毎秒5,000万命令）です。

**方式2：5段固定マルチサイクルプロセッサ（1命令＝5サイクル）**
[0-3節](0-3.md)で学んだ「クリティカルパスの途中にレジスタを挿入する」発想を適用し、IF・ID・EX・MEM・WBの各ステージ間に中間レジスタを置いて、1サイクルに1ステージずつ進める方式です。1サイクルに1ステージしか動かさないため、**命令とデータでメモリを1つにまとめたり、PC加算とALU演算で加算器を1つに共有したりしてハードウェアの回路規模（面積・コスト）を削減できる**のが本来の利点です。クロック周期は**最も遅い単一ステージ（IFとMEMの $5\text{ ns}$）**に合わせれば済みます。

$$T_{\text{clk}} = \max(5, 4, 4, 5, 2) = \mathbf{5\text{ ns}}$$

* 動作周波数：$f = \frac{1}{5 \times 10^{-9}\text{ s}} = \mathbf{200\text{ MHz}}$（シングルサイクルの**4倍**に向上）です。
* 1サイクルあたり完了命令数：1命令に5サイクルかかるため $\text{IPC} = \frac{1}{5} = \mathbf{0.2}$ です。
* 性能：$\text{Performance} = 200\text{ MHz} \times 0.2 = \mathbf{40\text{ MIPS}}$（毎秒4,000万命令）です。

回路規模は小さく抑えられ、周波数も $50\text{ MHz}$ から $200\text{ MHz}$ へ4倍に上がりましたが、**処理性能（スループット）は 50 MIPS から 40 MIPS へむしろ低下**しました（図0-4-2）。理由は2つあります。第1に、各ステージの遅延が均等でないため（WBは $2\text{ ns}$ しかないのに $5\text{ ns}$ 待たされる）、1命令あたりの実時間が $20\text{ ns}$ から $5\text{ ns} \times 5 = 25\text{ ns}$ へ伸びたためです。第2に、1つの命令がWBを終えるまで次の命令を始めないため、IF〜MEMの各回路が5サイクル中4サイクルは遊休状態になってしまうためです。

> **【コラム：常に `0` を返すレジスタ `x0` と、x86-64 のゼロ化イディオム】**
>
> RISC-Vの32本の汎用レジスタのうち、先頭の **`x0`（別名 `zero`）は値が常に `0` に固定されており、何を書き込もうとしても無視されます**。貴重なレジスタを1本つぶしてまで `0` 専用にするのはもったいなく見えますが、これによって命令セットアーキテクチャ（**ISA**：Instruction Set Architecture）とハードウェア回路の双方が大幅に簡潔になります。
>
> * **専用命令を減らせる（疑似命令の実現）：** アセンブラが基本命令へ展開してくれる簡略表記（**疑似命令**）の多くを `x0` で統一できます。たとえばレジスタ間のコピー `mv rd, rs` は `addi rd, rs, 0`、定数の読み込み `li rd, imm` は `addi rd, x0, imm`、何もしない命令 `nop` は `addi x0, x0, 0` として定義できます。さらに、戻り先アドレスを保存して飛ぶ関数呼び出し命令 `jal rd, label` で `rd = x0` を指定すれば、戻り先を捨てて単純にジャンプする無条件ジャンプ `j label`（＝ `jal x0, label`）まで1つの命令形式で賄えます。
> * **書き込み制御回路が単純になる：** データパスのWBステージでレジスタへの書き込みが不要な命令（`sw` や `beq` など）を処理するとき、書き込み先番号を強制的に `rd = 0`（`x0`）に差し替えるだけで、余計な書き込み抑止の分岐を設けずに安全に結果を捨てられます。
>
> 一方、ゼロレジスタを持たない **x86-64**（[第1部](../index.md#part-1) [1-1節](../1/1-1.md)で詳述）では、レジスタを `0` にするために `mov eax, 0`（5バイト）ではなく、自分自身との排他的論理和をとる **`xor eax, eax`**（2バイト）が広く使われます。現代のx86-64 CPUのデコーダは、この `xor eax, eax` を「**ゼロ化イディオム（Zeroing Idiom）**」として特別に認識し、ALU演算を一切使わずにデコード段階で直ちに `0` を割り当てる最適化を行っています。ゼロという定数をどう低コストに扱うかにも、RISCとCISCそれぞれの設計思想が表れています。

### 4. 限界と補正（Critique & Adaptation）

3-(3)の数値比較で見えた通り、シングルサイクル方式にも固定マルチサイクル方式にも明確な限界があります。

#### (1) シングルサイクル方式の限界と、マルチサイクルにおける状態遷移最適化

シングルサイクル方式の最大の弱点は、**めったに出現しない最も遅い命令（`lw`）の遅延に、頻繁に出現する軽い命令（`add` や `beq`）のクロック周期まで引きずられる**ことです。また、1クロックの間に命令メモリとデータメモリの両方を同時に参照し、さらに `PC + 4` 用・分岐先計算用・ALU本体の加算器をすべて別々に用意しなければならないため、回路規模も大きくなります。

これに対するマルチサイクル方式側での最初の補正が、**不要なステージを省略する状態遷移最適化（可変サイクル化）**です（図0-4-3）。

* **`beq`：** `IF → ID → EX → IF`（**3サイクル**）です。
* **`add`, `addi`：** `IF → ID → EX → WB → IF`（**4サイクル**）です。
* **`sw`：** `IF → ID → EX → MEM → IF`（**4サイクル**）です。
* **`lw`：** `IF → ID → EX → MEM → WB → IF`（**5サイクル**）です。

たとえば実行される命令の割合が `beq: 10%`、`lw: 10%`、`add/addi/sw: 80%` だとすると、平均サイクル数（CPI）は

$$\text{CPI} = 0.10 \times 3 + 0.10 \times 5 + 0.80 \times 4 = 0.3 + 0.5 + 3.2 = \mathbf{4.0 \text{ サイクル}}$$

となり、$\text{IPC} = 1 / 4.0 = 0.25$ へ改善します。先ほどの $200\text{ MHz}$ の例では $\text{Performance} = 200 \times 0.25 = \mathbf{50\text{ MIPS}}$ となり、ようやくシングルサイクルと並びます。

#### (2) マルチサイクル方式の本質的な限界（次節パイプラインへの動機）

状態遷移を最適化してさえ、マルチサイクル方式の $\text{IPC}$ は $0.25$ 程度（4サイクルに1命令）に留まり、シングルサイクル方式を大きく超えるスループットは得られません。根本原因は、**「1つ目の命令がMEMやWBを進んでいる間、すでに仕事が終わって空いているIF・ID・EXの回路を遊ばせている」**ことにあります。

もし、工場の流れ作業（ベルトコンベア）のように、1つ目の命令がIDへ進んだ瞬間に2つ目の命令をIFへ投入し、全5ステージを毎サイクル同時に稼働させられれば、クロック周波数をマルチサイクル並みの **$200\text{ MHz}$** に保ったまま、理想的には **$\text{IPC} \approx 1.0$**（$\text{Performance} \approx 200\text{ MIPS}$、シングルサイクルの**4倍**）を達成できます。この発想こそが、次節（[0-5節](0-5.md)）で導入する**パイプライン処理**です。

### 5. 接続と展望（Bridge）：本節の内容が後半のどの部に繋がるか

    本節で組み立てた5ステージのデータパス（IF・ID・EX・MEM・WB）をそのまま使い、複数命令をステージ単位で重ねて並列実行する**5段パイプライン**へ発展させます。

2. **[第1部](../index.md#part-1)（[1-1](../1/1-1.md)・[1-2節](../1/1-2.md)：ISAの設計思想と機械語命令）：**
    本節のRISC-V（固定長32ビット・ロード／ストアアーキテクチャ）と、x86-64（可変長・メモリ直接演算ありのCISC）の設計思想の違いを対比します。

3. **[第3部](../index.md#part-3)（[3-3](../3/3-3.md)・[3-6節](../3/3-6.md)：コンテクストスイッチとトラップ処理）：**
    本節で登場した `PC` と汎用レジスタ `x0`〜`x31` の組こそが、OSがプロセスを切り替えるときに丸ごと退避・復元する「CPUの状態（コンテクスト）」の実体になります。

### 理解度チェック（次節へ進む前の確認）

本節の制御信号・性能式 $\text{Performance} = f \times \text{IPC}$・5ステージの実行トレースを確認し、次節（[0-5節](0-5.md)）へ繋ぐ問いを置きます。

> **【確認の問い】**
>
> 1. **（`sw`・`beq` の制御信号と `RegWrite` バグ・`x0` 保護の診断）**
>     図0-4-1 の RISC-V 最小データパスで、ストア命令 `sw x3, 8(x7)` と条件分岐命令 `beq x1, x2, offset` を実行するときの制御信号を確認します。
>
>     * (a) `sw` と `beq` それぞれについて、**ALU第2入力のMUX**（`rs2` か `imm` か）、**レジスタ書込み許可（`RegWrite`）**（`0` か `1` か）、**データメモリ書込み許可（`MemWrite`）**（`0` か `1` か）の3つを答えてください。
>     * (b) もし回路のバグで `sw` 実行時に誤って `RegWrite = 1` にしてしまった場合、レジスタファイルに何が起きるでしょうか。また、本節コラムで触れた `x0` レジスタの性質を使うと、どのような工夫で誤書込みを防げるでしょうか。
>
> 2. **（可変長マルチサイクル方式がシングルサイクルを上回る CPI 閾値）**
>     各ステージの遅延が IF: $4\text{ ns}$、ID: $3\text{ ns}$、EX: $4\text{ ns}$、MEM: $6\text{ ns}$、WB: $3\text{ ns}$ であるプロセッサを考えます（レジスタ遅延は無視）。
>
>     * (a) シングルサイクル方式のクロック周期 $T_{\text{clk}}$、動作周波数 $f$（MHz）、および性能（MIPS）を求めてください。
>     * (b) マルチサイクル方式（クロック周期は最遅ステージに一致）で不要ステージを省略する可変サイクル最適化を行ったとき、シングルサイクル方式の性能を上回るには平均 $\text{CPI}$ がいくつ未満である必要があるでしょうか（小数第2位まで）。また、本節の最小5命令（`beq`: 3サイクル、`add`/`addi`/`sw`: 4サイクル、`lw`: 5サイクル）の組み合わせで現実のプログラムがその閾値を達成できるか考察してください。
>
> 3. **（1サイクルずらして重ねたときの資源使用トレース：次節への橋渡し）**
>     本節4-(2)の最後に触れた「流れ作業」のアイデアを確かめるため、次の2命令を1サイクルずつずらして同時に動かしてみます（命令1は CC1 で IF 開始、命令2は CC2 で IF 開始）。
>
>     ```asm
>     lw  x5, 8(x7)     # 命令1（CC1: IF, CC2: ID, CC3: EX, CC4: MEM, CC5: WB）
>     add x6, x5, x1    # 命令2（CC2: IF, CC3: ID, CC4: EX, CC5: MEM, CC6: WB）
>     ```
>
>     * (a) CC1〜CC6 の各サイクルで命令1と命令2がどのステージにいるかを整理したうえで、もし命令メモリとデータメモリが分離されておらず1つの単一メモリだった場合、さらに2命令後（CC4 で IF に入る命令4）と命令1の間でどのサイクルにメモリの奪い合いが起きるか答えてください。
>     * (b) 命令1が `x5` へ読み出した値を書き戻すサイクル（WB）と、命令2が `x5` の値をレジスタファイルから読み出すサイクル（ID）を比べ、そのまま動かすと何が起きるかを説明してください。
