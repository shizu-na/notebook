### 前節（6-2）の確認問題の解答

前節の最後に提示した3つの問いの解答を確認します。

1. **Shannon-Hartley の定理：帯域幅 $B$ 拡大 vs 送信電力 $S$ 増強の比較：**

    * **(a) 現在の最大通信路容量 $C_0$：**

        $$C_0 = 10 \times 10^6 \times \log_2(1 + 15) = 10 \times 10^6 \times \log_2(16) = 10 \times 10^6 \times 4 = \mathbf{40\text{ Mbps}}$$

    * **(b) $C_1$（帯域 2 倍）と $C_2$（電力 17 倍）の比較：**

        * ① 帯域幅 $B = 20\text{ MHz}$、$S/N = 15$ の場合：$C_1 = 20 \times 10^6 \times \log_2(16) = 20 \times 4 = \mathbf{80\text{ Mbps}}$ です。
        * ② 帯域幅 $B = 10\text{ MHz}$、$S/N = 255$ の場合：$C_2 = 10 \times 10^6 \times \log_2(256) = 10 \times 8 = \mathbf{80\text{ Mbps}}$ です。

        どちらも同じ $80\text{ Mbps}$ に達しますが、$C$ は $B$ に比例するのに対し $S/N$ には対数でしか伸びないため、電力を 17 倍にするよりも帯域幅を 2 倍に広げる方がはるかに効率的です。

    * **(c) $B \to \infty$ でも容量が無限にならない理由：**
        白色雑音では雑音電力自体が $N = N_0 B$ と帯域幅に比例して増大するため、送信電力 $S$ が一定のまま $B \to \infty$ としても $S/N$ が低下し、通信路容量は $\dfrac{S}{N_0 \ln 2} \approx 1.44\,\dfrac{S}{N_0}$ という有限の上限へ収束します。

2. **Hamming(7,4) 符号の 1 ビット訂正と 2 ビット誤りによる誤訂正：**

    * **(a) 受信語 `1 0 1 1 1 1 0`（$b_1=1, b_2=0, b_3=1, b_4=1, b_5=1, b_6=1, b_7=0$）のシンドロームと復元：**

        $$
        \begin{aligned}
        s_1 &= b_1 \oplus b_3 \oplus b_5 \oplus b_7 = 1 \oplus 1 \oplus 1 \oplus 0 = \mathbf{1} \\
        s_2 &= b_2 \oplus b_3 \oplus b_6 \oplus b_7 = 0 \oplus 1 \oplus 1 \oplus 0 = \mathbf{0} \\
        s_4 &= b_4 \oplus b_5 \oplus b_6 \oplus b_7 = 1 \oplus 1 \oplus 1 \oplus 0 = \mathbf{1}
        \end{aligned}
        $$

        $(s_4 s_2 s_1)_2 = (101)_2 = \mathbf{5}$ となるため、誤りは**位置 5** です。位置 5 を `1 → 0` へ反転した正しい符号語は **`1 0 1 1 0 1 0`**、元の 4 ビットデータ $(d_3 d_5 d_6 d_7)$ は **`1010`** です。

    * **(b) 2 ビット同時反転（位置 1・2 反転 $\to$ `1 0 1 0 0 1 1`）による誤訂正：**
        受信語 `1 0 1 0 0 1 1` のシンドロームは $s_1 = 1 \oplus 1 \oplus 0 \oplus 1 = 1$、$s_2 = 0 \oplus 1 \oplus 1 \oplus 1 = 1$、$s_4 = 0 \oplus 0 \oplus 1 \oplus 1 = 0$ より $(s_4 s_2 s_1)_2 = (011)_2 = \mathbf{3}$ になります。受信側は「位置 3 の 1 ビット誤り」と誤認して位置 3 を反転してしまい、別の正規符号語 **`1 0 0 0 0 1 1`**（誤ったデータ **`0011`**）へ誤訂正してしまいます。

3. **ビットスタッフィング境界トレースと CRC の $\text{GF}(2)$ 計算：**

    * **(a) 送信データ `01111101111110` のビットスタッフィングと復元：**
        先頭から走査して `1` が 5 個連続するたびに（次のビットが `0` か `1` かによらず）ダミーの `0` を 1 ビット挿入すると、前半の `011111` の直後と後半の `11111` の直後にそれぞれ `0` が挿入され、伝送路上のビット列は **`011111[0]011111[0]10`**（＝ **`0111110011111010`**、16 ビット）になります。受信側は `1` が 5 個連続した直後の `0` を 2 箇所とも削除することで、元の `01111101111110` を一意に復元できます。

    * **(b) CRC 計算（$D = \texttt{11001}$, $G = \texttt{1011}$, $r = 3$）と改ざん耐性の欠如：**
        `11001000` を `1011` で左から XOR 除算します。

        ```text
        11001000
        1011      (位置 0..3 を XOR)
        ----
         1111     (位置 1..4)
         1011     (位置 1..4 を XOR)
         ----
          1000    (位置 2..5)
          1011    (位置 2..5 を XOR)
          ----
            1100  (位置 4..7：位置 3 は 0 のためスキップ)
            1011  (位置 4..7 を XOR)
            ----
             111  ← 下位 3 ビットが余り R = 111
        ```

        したがって余りは **$R = \texttt{111}$**、送信フレームは **`11001111`**（8 ビット）です（検算：`11001111` を `1011` で割ると余り `000` になります）。なお、CRC は公開の生成多項式 $G$ を用いる暗号鍵のない線形計算であるため、攻撃者はデータを任意に書き換えたうえで新しいデータに対する正しい CRC を再計算して付け替えられ、改ざんを検知できません。

## 6-3. 多重アクセス制御（ALOHA解析・CSMA/CD・無線LANと隠れ端末）

### 1. 動機（Why）：1つの共有媒体へ複数台が繋がるとき、なぜ「交通整理（MAC）」が必要になるのか

前節（[6-2節](6-2.md)）では、1対1のリンク（ポイントツーポイントリンク）の上で0と1を正確に運ぶ仕組みを学びました。しかし、現実のネットワークには **複数のノードが1つの物理媒体を共有するリンク（ブロードキャストリンク）** が広く存在します。

* 初期のイーサネットでは、1本の同軸ケーブルやリピータハブへ多数の PC がぶら下がる構成が使われていました。
* 現代の無線 LAN（Wi-Fi）では、同じ周波数チャネルの電波空間を部屋中のスマートフォンや PC が共有しています。
* 携帯電話網の基地局と多数の端末のあいだや、衛星通信のアップリンクでも同一の無線帯域を共有します。

このような共有媒体では、あるノードが送信した信号は他のすべてのノードへ同時に届きます。もし2台以上のノードが同じ瞬間に送信を開始すると、電気信号や電波が物理的に重なり合って波形が崩れ、受信側はどちらのデータも解読できなくなります（**衝突：Collision**）。衝突が起きると、その時間帯の通信路帯域は丸ごと無駄になります。

この問題を解決するため、リンク層には **多重アクセスプロトコル（MAC：Medium Access Control）** と呼ばれる分散型の交通整理ルールが組み込まれています。本節では、MACプロトコルの全体分類を押さえたうえで、歴史的な出発点である **ALOHA の数理解析**、有線LANの基盤を築いた **CSMA/CD**、そして無線LAN特有の難題（**隠れ端末問題**）に挑む **CSMA/CA** を順に解き明かします。

---

### 2. 具体例と動作イメージ（Toy Model）

数式やプロトコル仕様に入る前に、共有媒体での譲り合いを日常の会話とケーブル上の信号伝搬に例えてイメージを固めます。

#### 実験A：暗い会議室で10人が「司会なし」で発言するルール

照明の消えた会議室（誰が手を挙げているか見えない）に10人が座り、1つの議題について発言するとします。

1. **ALOHA 方式（思いついたら即喋る）：** 他の人が喋っているか確認せず、言いたいことが浮かんだ瞬間に話し始めます。声が被ったら（衝突）、しばらくバラバラのランダム時間だけ待ってから言い直します。
2. **CSMA 方式（聴いてから喋る：Listen before Talk）：** 発言する前にまず耳を澄まし、誰かが話していれば黙って待ち、静かになってから話し始めます。衝突は大きく減りますが、「2人がまったく同じ瞬間に静寂を確認して同時に話し始める」衝突まではゼロにできません。
3. **CSMA/CD 方式（喋りながら聴く：有線）：** 自分が話している最中も耳を澄まし、他人の声と被ったと気づいた瞬間に**途中で話を打ち切って**ランダム時間だけ待ちます。無駄に最後まで喋り続けないため、衝突による時間ロスを最小化できます。
4. **CSMA/CA 方式（無線）：** 無線では「自分の声が耳元で大きすぎて、遠くから来る他人の微弱な声が聞き取れない（衝突検出ができない）」ため、話し始める前に少しランダムに譲り合ったり、事前に「これから話します（RTS）」「どうぞ（CTS）」と予約を入れたりして衝突自体を回避します。

#### 実験B：有線ケーブルで「衝突に気づく前に送信が終わってしまう」問題

CSMA/CD（喋りながら衝突を検出する）には、物理的な伝搬遅延 $d_{\text{prop}}$ に由来する重要な制約があります。

長さ $d$ のケーブルの左端にホスト A、右端にホスト B がおり、片道の伝搬遅延が $d_{\text{prop}}$ だとします。

1. 時刻 $t = 0$ にホスト A がフレーム送信を開始します。その先頭ビットが右端の B へ届くのは $t = d_{\text{prop}}$ です。
2. 届くほんの一瞬前（$t = d_{\text{prop}} - \varepsilon$）に、B はまだ A の信号を見ていないため「回線は空いている」と判断して送信を開始します。直後に A と B の信号が B の手前で衝突します。
3. この衝突信号がケーブルを逆走して左端の A へ戻ってくるのは、最悪で **$t \approx 2 d_{\text{prop}}$**（往復伝搬遅延）の時点です。

もし A が送るフレームが極端に短く、**時刻 $2 d_{\text{prop}}$ より前に A が全ビットを送り終えてしまっていたら**、A は「衝突せずに正常に送り終えた」と勘違いしてフレームを捨ててしまいます。したがって、CSMA/CD が確実に衝突を検出するためには、**フレームの伝送遅延 $L/R$ が往復伝搬遅延 $2 d_{\text{prop}}$ 以上であること（$L/R \ge 2 d_{\text{prop}}$）**が物理的な必須条件になります。

### 3. 構造・アルゴリズム・実装（What）

#### (1) 多重アクセスプロトコルの 3 大分類

共有媒体を複数ノードで分け合うプロトコルは、大きく次の3つのアプローチに分類されます。

| 分類 | 代表方式 | 仕組みと特徴 |
| :--- | :--- | :--- |
| **1. チャネル分割型（固定割当）** | TDMA（時間分割）、FDMA（周波数分割）、CDMA（符号分割） | 帯域を固定スロットや周波数へ事前分割して配る。高負荷時は衝突ゼロで公平だが、低負荷時に空きスロットが無駄になる（[6-1節](6-1.md)の回線交換と同型）。 |
| **2. ランダムアクセス型** | **ALOHA、CSMA/CD、CSMA/CA** | 事前割当をせず、送りたいノードが全帯域を使って送信。衝突が起きたらランダム待機して再送。低負荷時に高速でスケーラブル。 |
| **3. 順番制（要求割当 / Taking-Turns）** | ポーリング（親局が順に指名）、トークンパッシング | 送信権（トークン）を順番に回す。衝突ゼロかつ高負荷時も効率的だが、トークン紛失時の回復や親局の単一障害点対策が必要。 |

LAN（イーサネットや Wi-Fi）では、端末の追加・離脱が頻繁でトラヒックがバースト的であるため、中央管理が不要な **ランダムアクセス型** が主軸となりました。

#### (2) Pure ALOHA と Slotted ALOHA のスループット数理解析

1970年にハワイ大学で島々を無線で結ぶために開発された **ALOHA** は、ランダムアクセス制御の数学的基礎を与えます。全ノードが同じ固定長フレーム（伝送時間 $T$）を送信し、ネットワーク全体で1フレーム時間 $T$ あたりに発生する送信試行（新規送信＋再送）の総数が平均 $G$ 回のポアソン過程に従うと仮定します（$G$ を**正規化トラヒック負荷**と呼びます）。

1フレーム時間あたりのスループット $S$（成功して届くフレーム数の期待値）は、送信試行率 $G$ に 1 回の送信が衝突せず成功する確率 $P(\text{success})$ を掛けて次のように表されます。

$$
S = G \times P(\text{success})
$$

ポアソン過程の性質より、長さ $\tau$ の時間区間内に他ノードからの送信開始がちょうど $k$ 回発生する確率は $\dfrac{(G \cdot \tau/T)^k}{k!} e^{-G \cdot \tau/T}$ です。特に「1回も発生しない（$k = 0$）」確率は $e^{-G \cdot \tau/T}$ になります。

1. **Pure ALOHA（純 ALOHA：時刻同期なし）：**
    あるノードが時刻 $t_0$ に送信を開始し、$t_0 + T$ に完了するとします。このフレームが他のフレームと1ビットも重ならず**成功する**ためには、

    * $t_0 - T$ から $t_0$ のあいだに他ノードが送信を開始していないこと（先行フレームの末尾と自フレームの先頭が被らない条件）
    * $t_0$ から $t_0 + T$ のあいだに他ノードが送信を開始していないこと（後続フレームの先頭と自フレームの末尾が被らない条件）

    の両方が必要です。つまり、**衝突の危険がある期間（脆弱期間：Vulnerable Period）は $2T$** です（図6-3-1左）。長さ $2T$ の区間に他ノードの送信開始が0回である確率は $P(\text{success}) = e^{-2G}$ なので、スループット $S$ は次式で与えられます。

    $$S_{\text{Pure}} = G \times e^{-2G} = G \, e^{-2G}$$

    $G$ で微分して $\dfrac{dS}{dG} = (1 - 2G) e^{-2G} = 0$ とおくと、**$G = 0.5$** で最大値をとり、

    $$S_{\text{Pure, max}} = \frac{1}{2e} \approx \mathbf{0.184} \quad (\mathbf{18.4\%})$$

    となります。つまり Pure ALOHA では、どれほど工夫しても通信路の **18.4%** しか有効に使えません。

2. **Slotted ALOHA（スロット付き ALOHA：時刻同期あり）：**
    全ノードの時計をフレーム長 $T$ ごとのスロット境界に同期させ、送信は必ず**スロットの先頭からのみ開始できる**ルールにします。スロット境界に整列させることで、前のスロットで始まったフレームは必ず自スロット開始前に終わり、次のスロットのフレームは自スロット終了後に始まるため、部分的な重なりが消滅します。衝突が起きるのは「まったく同じスロット（幅 $T$）の先頭で他ノードも送信を開始した場合」だけになるため、**脆弱期間が $2T$ から $T$ へ半減**します（図6-3-1左下）。
    長さ $T$ の区間に他ノードの送信が0回である確率は $P(\text{success}) = e^{-G}$ なので、スループットは

    $$S_{\text{Slotted}} = G \times e^{-G} = G \, e^{-G}$$

    となり、**$G = 1.0$** で最大値

    $$S_{\text{Slotted, max}} = \frac{1}{e} \approx \mathbf{0.368} \quad (\mathbf{36.8\%})$$

    へとちょうど **2 倍** に向上します（図6-3-1右）。さらに $G$ が最適値を超えると、衝突と再送が雪だるま式に増えてスループットが急落する（**輻輳不安定**）こともグラフから読み取れます。

#### (3) 有線 LAN の CSMA/CD と 2 進指数バックオフ（BEB）

ALOHA の効率が最大 36.8% に留まった理由は、「他人が送信中かを確認しない（キャリアセンスなし）」ことと「衝突しても最後まで無駄に送り続ける（衝突検出なし）」ことでした。1973年にロバート・メトカーフらが考案したイーサネットの **CSMA/CD（Carrier Sense Multiple Access with Collision Detection）** は、この2つをハードウェアへ組み込むことで実効効率を 80%〜90% 以上へ引き上げました（図6-3-2）。

CSMA/CD の動作手順は次の5ステップです。

1. **キャリアセンス（CS：搬送波感知）：** 送信前に物理媒体上の信号を監視します。他ノードが送信中（ビジー）なら、回線が空く（アイドルになる）まで待ちます。
2. **送信開始と同時監視（CD：衝突検出）：** アイドルになったら送信を開始し、同時に自分の送信波形とケーブル上の受信波形を比較し続けます。
3. **衝突検出とジャム信号：** 電圧の異常な重なり（衝突）を検出したら、**即座にデータ送信を打ち切り**、ケーブル上の衝突波形が短すぎて他ノードが衝突を見逃すのを防ぐため、意図的に **32ビットのジャム信号（Jam Signal）** を送出して全端末へ衝突発生を確実に通知します。
4. **2進指数バックオフ（BEB：Binary Exponential Backoff）：** 衝突直後に両ノードがすぐ再送すると再び衝突（ライブロック）するため、$n$ 回目の連続衝突後は集合 $\{0, 1, 2, \dots, 2^{\min(n, 10)} - 1\}$ から一様ランダムに整数 $K$ を選び、**$K \times 512$ ビット時間（スロット時間：最小フレーム 64 B の送出時間に相当）** だけ待機してからステップ1へ戻ります（16回連続で失敗したら上位層へエラーを返して諦めます）。
5. **送信完了：** 衝突せずに最後まで送り切れば成功です。

2進指数バックオフは巧みな自己適応アルゴリズムです。参加台数が2台だけなら $K \in \{0, 1\}$ で即座に再送でき、逆に100台が同時に衝突する高混雑時には $n$ が増えるにつれて待機幅が $2, 4, 8, \dots, 1024$ 倍へと指数関数的に広がり、ネットワークの混雑を自律的に鎮静化させます。

> **【コラム：なぜ古典的イーサネットの最小フレーム長は「64 バイト」なのか】**
>
> イーサネットの規格（IEEE 802.3）では、たとえ送信したいアプリデータが1バイトしかなくても、フレーム全体が必ず **64 バイト（512 ビット）以上** になるように末尾へ `0` のパディングを詰める決まりになっています。この「64バイト」という数字は任意に決められたわけではなく、図6-3-2の物理不等式 $L / R \ge 2 d_{\text{prop}}$ から直接導かれた値です。
>
> 初期の 10 Mbps イーサネット（$R = 10^7\text{ bit/s}$）では、ケーブルの最大長と途中のリピータ遅延を合わせた往復伝搬遅延の上限（スロット時間）が **$51.2\ \mu\text{s}$** と定められました。この時間だけ送信し続けるために必要な最小ビット数は、
>
> $$L_{\min} = R \times 2 d_{\text{prop}} = 10^7\text{ bit/s} \times 51.2 \times 10^{-6}\text{ s} = \mathbf{512\text{ bit} = 64\text{ バイト}}$$
>
> となります。後に 100 Mbps（Fast Ethernet）へ10倍高速化した際は、64バイトの最小フレーム長（スロット時間 512 ビット時間）を維持する代わりにケーブル長の上限を約10分の1（リピータ遅延込みで約 $200\text{ m}$）へ縮めることで整合を保ちました。通信プロトコルの数値仕様の裏には、常に光速と帯域の物理制約が刻まれています。

#### (4) 無線 LAN（IEEE 802.11 / Wi-Fi）の CSMA/CA と隠れ端末問題

有線LANで広く普及した CSMA/CD ですが、これを **無線LAN（Wi-Fi：IEEE 802.11）** へそのまま持ち込むことはできません。無線空間には、有線ケーブルにはない **2つの根本的な物理特性** があるためです。

1. **衝突検出（CD）が事実上できない：** 電波は距離の2乗〜4乗に反比例して急激に減衰するため、自分のアンテナの送信電力は、遠くの他端末から届く微弱な受信信号より何百万倍も強くなります。自分の送信電波が自機の受信回路を圧倒してしまい、「送信しながら他人の衝突を聞き分ける」ことが困難です。
2. **電波の到達範囲が局所的である（隠れ端末・さらし端末問題）：** 有線ケーブルでは全ノードが同じ信号を共有しますが、無線では距離や壁によって「Aの電波はB（アクセスポイント）には届くが、反対側のCには届かない」という非対称な状況が常に起きます（図6-3-3左）。

    * **隠れ端末問題（Hidden Terminal Problem）：** A と C は互いに電波が届かないため、A が B へ送信中でも、C はキャリアセンスで「空間は静か（アイドル）だ」と誤認して B へ送信を開始し、**受信側の B で衝突が発生**します。
    * **さらし端末問題（Exposed Terminal Problem）：** 逆に、B が A へ送信しているとき、B の近くにいる C は B の電波を検知して「ビジーだ」と判断し、**本来は B の反対側にいる D へ干渉せずに同時送信できるはずなのに送信を控えてしまう**（帯域の機会損失）現象です。

そこで Wi-Fi（IEEE 802.11）は、「衝突を検出して止める（CD）」のではなく、**「衝突を事前に避け（CA：Collision Avoidance）、届いたことを必ず確認応答（ACK）で確かめる」** **CSMA/CA** を採用しています（図6-3-3右）。

* **基本動作（DCF：分散協調機能）：**

    1. 送信したい端末は、チャネルが **DIFS（Distributed Inter-Frame Space：規定の待機時間）** だけ連続してアイドルであることを確認します。
    2. アイドルを確認した直後にいきなり送信せず、さらに **ランダムなバックオフ時間** だけカウントダウンして待ちます（他端末がビジー明けに一斉送信する衝突を回避します）。途中で他人が話し始めたらカウントダウンを一時停止します。
    3. カウントダウンが `0` になったらフレームを最後まで送り切ります。
    4. 受信側（AP等）は CRC に誤りがなければ、DIFS より短い間隔 **SIFS（Short Inter-Frame Space）** の後に **ACK フレーム** を返します。送信側が ACK を受け取れなければ衝突またはノイズで失敗したとみなし、バックオフ範囲を2倍に広げて再送します。

* **RTS / CTS（MACA の考え方を採り入れた仮想キャリアセンス）による隠れ端末の予約回避：**
    大きなフレームを送る際、送信元 A はまず短い予約要求 **RTS（Request to Send）** を宛先 B へ送り、B が全周囲へ **CTS（Clear to Send）** を返します。RTS と CTS には「これから何マイクロ秒間チャネルを使うか」という期間情報が書かれており、A の電波が届かない隠れ端末 C も **B からの CTS を受信** して、自機のタイマ（**NAV：Network Allocation Vector**）をセットして指定期間だけ送信を控えます。これにより、隠れ端末による長いデータフレームの衝突を効果的に防止できます。ただし、短いデータフレームでは RTS / CTS 交換自体のオーバーヘッドの方が大きくなるため実務では一定サイズ以上のフレームにのみ適用され、また **さらし端末問題（干渉しない別方向への同時送信抑止）自体は RTS / CTS では解決できません**。

### 4. 限界と補正（Critique & Adaptation）

#### (1) 有線 CSMA/CD の限界と「全二重スイッチド・イーサネット」への移行

CSMA/CD は同軸ケーブルやリピータハブで全端末が1つの物理媒体を共有する時代に広く使われましたが、ネットワーク速度が $1\text{ Gbps}$・$10\text{ Gbps}$ へと上がるにつれて2つの限界が露呈しました。

1. **物理距離の制約：** 最小フレーム長 64 バイト（512 bit）を保ったまま速度 $R$ を 100 Mbps（実用規格上限：リピータ遅延込みで約 $200\text{ m}$）から 10 倍（1 Gbps）・100 倍（10 Gbps）へ上げると、許容ケーブル長はそれぞれ約 $20\text{ m}$・約 $2\text{ m}$ に縮まります（リピータ遅延のない理論式 $L_{\min} = 2Rd/s$ でも 100 Mbps で $512\text{ m}$、1 Gbps で約 $51.2\text{ m}$、10 Gbps で約 $5.1\text{ m}$ が上限となります）。逆にケーブル長を保とうとして最小フレーム長を 640 B や 6,400 B へ拡張すると、小パケットのパディング効率が著しく悪化します。
2. **衝突ドメインの肥大化：** 同じ共有媒体へ繋がる端末数が増えるほど衝突確率が上がり、全体のスループットが頭打ちになります。

これに対する有線LANの抜本的な補正が、次節（[6-4節](6-4.md)）で学ぶ **L2 スイッチ（スイッチングハブ）による「ポートごとの独立リンク化」と「全二重通信（Full-Duplex）」** です。各PCとL2スイッチを送信専用線と受信専用線のペアで1対1に直結することで、**有線LAN上から物理的な「衝突」そのものを構造的に消滅**させました（現代の 1 Gbps / 10 Gbps イーサネットでは CSMA/CD は事実上使われていません）。

#### (2) 無線 LAN の高密度混雑と Wi-Fi 6/7（OFDMA・BSS Coloring）による補正

一方、無線空間（電波）はケーブルのように1本ずつ物理分離できないため、現在も CSMA/CA が不可欠です。しかし、駅やカフェ・スタジアムのように1つのアクセスポイントへ数十〜数百台のスマホが密集すると、CSMA/CA のランダムバックオフと制御フレーム（RTS/CTS/ACK）のオーバーヘッドだけで電波空間が埋め尽くされて実効速度が大きく低下します。

これに対する現代 Wi-Fi（**Wi-Fi 6 [802.11ax] / Wi-Fi 7 [802.11be]**）の補正は、ランダムアクセス一辺倒から**チャネル分割とスケジュール制御の融合**へ進むことです。

* **OFDMA（直交周波数分割多元接続）：** 1つのチャネル（$20\text{ MHz}$ 等）を細かな周波数サブキャリア群（**RU**：Resource Unit）へ分割し、アクセスポイントの主導で**複数端末の小パケットを同時に並列送受信**します（ランダムアクセスと FDMA/TDMA のハイブリッド）。
* **BSS Coloring（空間再利用）：** 隣の部屋の Wi-Fi 電波に別の「色（識別番号）」を付け、干渉が十分弱ければさらし端末問題を回避して同時送信を許可します。

### 理解度チェック（次節へ進む前の確認）

本節の ALOHA 解析・CSMA/CD の物理条件と高速化トレードオフ・無線 LAN の隠れ端末とさらし端末を確認する問いを置きます。

> **【確認の問い】**
>
> 1. **（Slotted ALOHA の輻輳崩壊計算と Pure ALOHA の脆弱期間）**
>     次の 2 つの問いに答えてください。
>
>     * (a) Slotted ALOHA（$S = G e^{-G}$）において、負荷が最適値 $G = 1.0$ から過負荷の $G = 2.0$ へ増えたときのスループット $S$（%）を求め（$e^{-1} \approx 0.368$、$e^{-2} \approx 0.135$ を用いてよい）、送信試行数を 2 倍にしたのにスループットが低下する理由を 1 文で説明してください。
>     * (b) Pure ALOHA の脆弱期間が Slotted ALOHA の 2 倍（$2T$）になる理由を、送信開始時刻 $t_0$ の前後の重なりに触れて簡潔に説明してください。
>
> 2. **（CSMA/CD の最大ケーブル長計算と 1 Gbps 化時の 3 対策比較）**
>     最小フレーム長 $L_{\min} = 64\text{ B}$（$= 512\text{ bit}$）、伝送速度 $R = 100\text{ Mbps}$（$= 10^8\text{ bit/s}$）、信号伝搬速度 $s = 2 \times 10^8\text{ m/s}$ の共有有線リンクで CSMA/CD を動作させます（リピータ遅延は無視します）。
>
>     * (a) 衝突検出条件 $L_{\min} / R \ge 2d / s$ から、このリンクで許容される最大ケーブル長 $d_{\max}$（$\text{m}$）を求めてください。
>     * (b) この回線を 10 倍の $R = 1\text{ Gbps}$ へ高速化するとき、CSMA/CD の制約に対して考えられる 3 つの対策（① 最大ケーブル長を短縮する、② 最小フレーム長を拡張する、③ 共有媒体をやめ全二重 L2 スイッチへ移行する）のトレードオフを比較し、現代の有線 LAN が③を採用した理由を説明してください。
>
> 3. **（4 ノード直線配置での隠れ端末・さらし端末判定と無線 CSMA/CD 不可の理由）**
>     無線端末 A, B, C, D が一直線上に等間隔で並んでおり、各端末の電波はすぐ隣の端末（A–B、B–C、C–D）までしか届かないとします。
>
>     * (a) ①「A が B へ送信中に C が B へ送信しようとする場合」と、②「B が A へ送信中に C が D へ送信しようとする場合」は、それぞれ「隠れ端末問題」と「さらし端末問題」のどちらに該当するでしょうか。理由とあわせて判定してください。
>     * (b) 無線 LAN で有線の CSMA/CD（送信しながらの衝突検出）が使えない物理的理由を 1〜2 文で説明してください。
