### 前節（7-3）の確認問題の解答

前節の最後に提示した3つの問いの解答を確認します。問3がそのまま本節（待ち行列理論とトラヒック数理）の導入になります。

1. **TCP Tahoe vs TCP Reno の 3 RTT 送信量比較と実効送信ウィンドウ（`cwnd = 12 MSS` で 3 重重複 ACK、`1 MSS = 1,460 B`）：**

    * **(a) `ssthresh` および 3 RTT 分の送信可能セグメント数：**
        3 重重複 ACK の発生時、両方式とも **`ssthresh = 12 / 2 = 6 MSS`** に設定されます。

        * **TCP Tahoe（`cwnd = 1 MSS` へ急落しスロースタート）：** 1 RTT 目 `1 MSS` → 2 RTT 目 `2 MSS` → 3 RTT 目 `4 MSS` となり、3 RTT 合計は $1 + 2 + 4 = \mathbf{7\text{ セグメント}}$ です。
        * **TCP Reno（`cwnd = ssthresh = 6 MSS` で輻輳回避）：** 1 RTT 目 `6 MSS` → 2 RTT 目 `7 MSS` → 3 RTT 目 `8 MSS` となり、3 RTT 合計は $6 + 7 + 8 = \mathbf{21\text{ セグメント}}$ です。高速リカバリの有無により、最初の 3 RTT だけでちょうど **3 倍** の差がつきます。

    * **(b) TCP Reno の 3 RTT 目（`cwnd = 8 MSS`）における実効送信ウィンドウ $W$：**
        `cwnd = 8 × 1,460 = 11,680 B`、受信側通知の `rwnd = 8,760 B`（$= 6 \times 1{,}460\text{ B}$）なので、

        $$W = \min(\text{rwnd},\; \text{cwnd}) = \min(8{,}760,\; 11{,}680) = \mathbf{8{,}760\text{ B}}\quad (\mathbf{6\text{ MSS}})$$

        となります。ネットワーク側（`cwnd`）に余裕があっても、フロー制御（`rwnd`）が受信バッファ溢れを防ぐ上限として機能します。

2. **Bufferbloat と QUIC / HTTP/3 の構造診断：**

    * **(a) Bufferbloat の発生メカニズムと ECN・BBR による改善：**
        この現象は **Bufferbloat（バッファ肥大化による高遅延）** と呼ばれます。Reno や CUBIC のような損失ベースの輻輳制御は「ルータの出力バッファが 100% 満杯になってパケットが廃棄されるまで送信レートを上げ続ける」ため、巨大なバッファを常に満杯に詰まらせ続け、通過パケットの待ち行列遅延を大きく悪化させます。**ECN** はバッファが溢れる前にルータが IP ヘッダへ混雑印（CE）を付与して廃棄なしで送信側を減速させることで改善し、**BBR** はパケットロスではなく実測のボトルネック帯域幅と最小伝搬遅延（RTprop）からキューを溜めない最適送信レートを維持することで改善します。

    * **(b) Wi-Fi → 5G 切替および 1% パケット紛失時の TCP（HTTP/2）と QUIC（HTTP/3）の違い：**

        * **Wi-Fi → 5G 切替時：** TCP は IP アドレスを含む **5 つ組** で接続を識別するため、IP アドレスが変わった瞬間に接続が切断され再確立が必要になります。QUIC はパケットヘッダ内の **接続 ID（Connection ID）** でセッションを識別するため、IP が変わっても接続を途切れさせずに継続（コネクションマイグレーション）できます。
        * **1% パケット紛失時：** HTTP/2（TCP 上）は複数ファイルを 1 本の単一バイトストリームに載せるため、1 パケット紛失すると再送完了まで他の無関係なファイル配送まで停止します（TCP 層 HoL ブロッキング）。QUIC（HTTP/3）は 1 接続内に互いに独立した複数ストリームを持つため、影響は欠損したストリームだけに留まり他ストリームは遅延なく配送されます。

3. **AIMD の収束座標計算と高利用率リンクでのキュー滞留（本節への接続）：**

    * **(a) 初期 $(90, 10)$ からの 2 回の輻輳損失の推移：**

        * **1 回目の半減直後：** 初期 $(90, 10)$（差 $80$）を半減して **$(45, 5)\text{ Mbps}$**、レート差は **$\vert 45 - 5 \vert = 40\text{ Mbps}$** です。
        * **2 回目の超過発生時：** 合計が $100$ を超えるまで $+10$ ずつ増やすと $(55, 15) \to (65, 25) \to \mathbf{(75, 35)\text{ Mbps}}$（合計 $110\text{ Mbps} > 100$）で 2 回目の超過が起きます（レート差は $40\text{ Mbps}$）。
        * **2 回目の半減直後：** $(75, 35)$ を半減して **$(37.5, 17.5)\text{ Mbps}$**、レート差は **$\vert 37.5 - 17.5 \vert = 20\text{ Mbps}$** へ縮まり、公平な $(50, 50)$ へ近づきます。

    * **(b) 利用率 $100\%$ 付近でのキュー滞留と RTT の変化：**
        パケットの平均到着率 $\lambda$ がリンクの処理能力 $\mu$ に迫る（利用率 $\rho = \lambda/\mu$ が $1$ に近づく）と、到着間隔のわずかな集中だけで出力バッファにパケットが滞留し始め、一時的な詰まりを解消する前に次の塊が到着してキュー長と待ち行列遅延（RTT）が急激に増大します。本節では、この非線形な遅延急増を **待ち行列理論** で定量的に導出します。

## 7-4. 待ち行列理論とトラヒック数理（$M/M/1$・リトルの公式・$M/M/S$・アーランB式）

### 1. 動機（Why）：なぜ「処理能力にまだ余裕がある」はずなのに、遅延が急増するのか

これまでの部と節の中で、私たちは何度も「待ち行列（キュー）」の振る舞いに直面してきました。

* **ネットワーク（[6-1](../6/6-1.md)・[7-3節](7-3.md)）：** ルータの出力バッファにパケットが溜まる待ち行列遅延 $d_{\text{queue}}$ や、バッファ肥大化による Bufferbloat が生じます。
* **OS（[3-3節](../3/3-3.md)）：** CPU コアの実行順番を待つレディキューでの応答時間が伸びます。
* **データベース（[第9部](../index.md#part-9)）：** トランザクションがロック解放やディスク I/O を待つ待機キューが発生します。

これらに共通する、直感に反する現象があります。たとえば「1秒間に最大 $100$ 個のパケットを処理できるルータ（処理率 $\mu = 100$）」に対し、平均して「1秒間に $90$ 個のパケットが到着する（到着率 $\lambda = 90$、利用率 $\rho = 90\%$）」状況を考えてみます。

一見すると、「まだ処理能力に $10\%$ も余裕があるのだから、待ち時間はほとんどゼロのはずだ」と思えます。ところが現実のルータや Web サーバでは、利用率が $50\%$ を超えたあたりから遅延が目立ち始め、$90\%$ で処理時間単体の **10 倍**、$99\%$ では **100 倍** へと跳ね上がります。

原因は **「到着の間隔と処理時間のランダム性（揺らぎ）」** にあります。平均では余裕があっても、偶然パケットが団子状に集中して到着した瞬間にキューが伸び、利用率が高いほどその一時的な渋滞がなかなか解消できなくなるためです。

この現象を経験則や勘ではなく、厳密な数学モデルで定量的に予測・設計するための道具が **待ち行列理論（Queueing Theory）** です。本節では、あらゆるシステムに成り立つ普遍法則 **リトルの公式** から出発し、基本モデル $M/M/1$、複数窓口モデル $M/M/S$、そして回線交換や接続上限設計の要である **アーランB式（$M/M/S/S$）** と派生モデルまでを一貫して整理します。

---

### 2. 具体例と動作イメージ（Toy Model）

数式の導出に入る前に、2つの小さな思考実験で「ランダム性が待ちを生む本質」と「窓口統合（統計的多重化）の効果」を確かめます。

#### 実験A：完全に規則正しい到着（$D/D/1$）vs ランダムな到着（$M/M/1$）

1個のパケット処理に平均 $10\text{ ms}$ かかるルータ（処理率 $\mu = 100\text{ パケット/秒}$）へ、平均して毎秒 $95$ 個のパケット（利用率 $\rho = 0.95$）が到着する 2 つの世界を比べます（$D$ は完全一定［Deterministic］、$M$ は指数分布に従うランダム到着／処理を表します）。

* **世界1（完全一定：$D/D/1$）：** パケットが機械仕掛けのように正確に $1/95\text{ 秒} \approx 10.53\text{ ms}$ おきに 1 個ずつ到着し、処理も正確に $10.0\text{ ms}$ で終わります。

    * 前のパケットが必ず $0.53\text{ ms}$ 前に処理を終えているため、**待ち時間は常に $0\text{ ms}$**、平均滞在時間は $10.0\text{ ms}$ のままです。

* **世界2（ランダム到着・ランダム処理：$M/M/1$）：** 到着間隔も処理時間も指数分布に従ってランダムに揺らぎます。

    * 偶然 3 個続けて到着した瞬間に後ろのパケットが待たされ、その渋滞を消化し切る前に次の塊が来ます。後述の公式で計算すると、平均滞在時間 $D$ は $10\text{ ms} \div (1 - 0.95) = \mathbf{200\text{ ms}}$（処理時間の **20 倍**）へ膨れ上がります。

つまり、**待ち行列の正体は「平均負荷」だけではなく「ランダム性（分散）$\times$ 利用率の高さ」** にあります。

#### 実験B：スーパーのレジ「2列バラバラ」vs「フォーク並び（1列統合）」

処理能力が同じレジが 2 台あるスーパーで、客の到着率が全体で $\lambda$ だとします。

1. **2 列バラバラ方式（独立した $M/M/1$ が 2 本）：** 客は到着時にランダムに半々（各列 $\lambda/2$）で左右どちらかのレジに並び、一度並んだら列を移りません。すると「右のレジは空いているのに、左のレジに 3 人並んでいる」という無駄な遊休が頻繁に起きます。
2. **フォーク並び方式（1 列に並んで空いたレジへ進む：$M/M/2$）：** どちらかのレジが空いた瞬間に必ず列の先頭客が案内されるため、「片方が遊んでいるのに客が待つ」現象が起きません。

同じレジ台数・同じ客数・同じ利用率 $\rho$ であっても、**窓口を 1 列に統合する（$M/M/S$）だけで平均待ち時間は大きく短くなります**（たとえば $\rho = 0.8$ のとき、$M/M/2$ の平均待ち時間は独立 $M/M/1$ 2本の約 **44%** まで半減します）。これは [6-1節](../6/6-1.md)の「統計的多重化」や、[3-3節](../3/3-3.md)のマルチコア・ワークスティーリングと同じ原理です。

### 3. 構造・アルゴリズム・実装（What）

#### (1) ケンドールの記号（Kendall's Notation）とポアソン過程・無記憶性

待ち行列モデルは、イギリスの統計学者デビッド・ケンドールが定めた $A / B / S / K$ という 4 記号（末尾 $K$ が $\infty$ のときは省略して $A/B/S$）で分類します。

* **$A$（到着過程の分布）：** 客・パケットの到着間隔の確率分布です（主な記号は **$M$**：ポアソン到着／指数分布、**$D$**：一定間隔［Deterministic］、**$G$**：任意の一般分布［General］）。
* **$B$（サービス時間の分布）：** 1 件の処理にかかる時間の確率分布です（同じく $M$・$D$・$G$ を使います）。
* **$S$（窓口数・サーバ数）：** 同時に並列処理できる回線や CPU コアの個数です。
* **$K$（系内最大収容数）：** 処理中＋待ち行列の合計上限です（省略時は無限バッファ $\infty$ を意味します）。

ここで最も基本となるのが **$M$（Markovian / Memoryless）** です。到着が平均到着率 $\lambda$［個/秒］の **ポアソン過程** に従うとき、到着間隔 $T$ はパラメータ $\lambda$ の **指数分布**（確率密度 $f(t) = \lambda e^{-\lambda t}$、平均 $1/\lambda$、標準偏差 $1/\lambda$）に従います。指数分布は平均と標準偏差が等しいため、ばらつきの度合いを表す **変動係数**（標準偏差 $\div$ 平均）が常に **$C_s = 1$** になります。指数分布が解析の主役になる理由は、次の **無記憶性（Memoryless Property）** を持つ唯一の連続確率分布だからです。

$$
P(T > t + s \mid T > s) = P(T > t)
$$

「すでに $s$ 秒間パケットが来なかった（あるいは処理が終わらなかった）としても、次の微小時間 $\Delta t$ に到着・完了する確率は過去 $s$ 秒の経過に一切依存せず、常に $\lambda \Delta t$（完了なら $\mu \Delta t$）である」という性質です。このおかげで、システムの状態は「今、系内に合計何個いるか（整数 $n$）」だけで記述でき（**マルコフ連鎖**）、過去を記憶せずに方程式を立てられます。

#### (2) リトルの公式（Little's Law）：$N = \lambda D$

待ち行列理論全体の中で最も普遍的な定理が、1961年にジョン・リトルが証明した **リトルの公式（Little's Law）** です。

定常状態（安定して動き続けている状態）にある任意のシステムにおいて、システム内（処理中＋待機中）にある平均個数を $N$、単位時間あたりの平均到着率を $\lambda$、1 個がシステムに入ってから出るまでの平均滞在時間（平均遅延）を $D$ とすると、次式が常に成り立ちます。

$$
N = \lambda D
$$

同様に、窓口を除いた「待ち行列の中だけ」に限定しても、平均待ち行列長 $L_q$ と平均待ち時間 $W_q$ の間に $L_q = \lambda W_q$ が成り立ちます。

リトルの公式の重要な特徴は、**到着分布 $A$ にもサービス分布 $B$ にも、窓口数 $S$ にも、処理順序（FIFO か LIFO かランダムか）にも一切依存しない**点です。直感的には、「ある客がシステムを出ていく瞬間に後ろを振り返ると、自分の滞在時間 $D$ のあいだに新しく到着してきた客が平均 $\lambda D$ 人だけシステム内に残っているはずだ」と捉えると理解しやすくなります。

たとえば Web サーバへ毎秒 $\lambda = 50$ リクエストが到着し、平均応答時間が $D = 0.2\text{ 秒}$ なら、サーバ内で同時処理中の平均リクエスト数は分布を問わず必ず $N = 50 \times 0.2 = \mathbf{10\text{ 件}}$ です。

#### (3) $M/M/1$ 待ち行列の導出（誕生死滅過程とホッケースティック曲線）

単一窓口・無限バッファの $M/M/1$ モデル（到着率 $\lambda$、処理率 $\mu$、**利用率 $\rho = \lambda / \mu < 1$**）を、状態遷移図（**誕生死滅過程：Birth-Death Process**）から導出します（図7-4-1左）。

系内にいるパケット総数（処理中＋待ち行列）が $n$ 個である定常確率を $P_n$ とします。隣り合う状態 $n$ と $n + 1$ のあいだで、定常状態では「右へ進む流量（到着）」と「左へ戻る流量（完了）」が釣り合っていなければなりません（**詳細釣り合い条件**）。

$$
\lambda P_n = \mu P_{n+1} \quad \Longrightarrow \quad P_{n+1} = \frac{\lambda}{\mu} P_n = \rho P_n
$$

これを $n = 0$ から順に繰り返し適用すると、$P_n = \rho^n P_0$ を得ます。全状態の確率の和は $1$ であり、$\rho < 1$ のとき無限等比級数の和は $\sum_{n=0}^{\infty} \rho^n = \dfrac{1}{1 - \rho}$ に収束するため、

$$
\sum_{n=0}^{\infty} P_n = P_0 \sum_{n=0}^{\infty} \rho^n = \frac{P_0}{1 - \rho} = 1 \quad \Longrightarrow \quad P_0 = 1 - \rho
$$

よって、系内数がちょうど $n$ 個である確率は幾何分布 $P_n = (1 - \rho)\rho^n$ となります（なお、利用率 $\rho = 1 - P_0$ は「窓口がビジーである確率」に一致します）。また、等比級数 $\sum_{n=0}^{\infty} \rho^n = (1-\rho)^{-1}$ の両辺を $\rho$ で微分して $\rho$ を掛けると $\sum_{n=1}^{\infty} n\rho^n = \dfrac{\rho}{(1-\rho)^2}$ が得られるため、ここから $M/M/1$ の 4 つの基本性能指標が連鎖的に導かれます。

1. **平均系内数 $N$：**

    $$
    N = \sum_{n=0}^{\infty} n P_n = (1 - \rho) \sum_{n=1}^{\infty} n \rho^n = (1 - \rho) \cdot \frac{\rho}{(1 - \rho)^2} = \mathbf{\frac{\rho}{1 - \rho}}
    $$

2. **平均系内時間（平均遅延）$D$：** リトルの公式 $D = N / \lambda$ と $\rho = \lambda / \mu$ より、

    $$
    D = \frac{N}{\lambda} = \frac{\rho}{\lambda(1 - \rho)} = \mathbf{\frac{1}{\mu(1 - \rho)} = \frac{1}{\mu - \lambda}}
    $$

3. **平均待ち時間 $W_q$：** 平均滞在時間 $D$ から自身の平均処理時間 $1/\mu$ を引いて、

    $$
    W_q = D - \frac{1}{\mu} = \frac{1}{\mu(1 - \rho)} - \frac{1}{\mu} = \mathbf{\frac{\rho}{\mu(1 - \rho)}}
    $$

4. **平均待ち行列長 $L_q$：** 再びリトルの公式 $L_q = \lambda W_q$ より、

    $$
    L_q = \lambda \cdot \frac{\rho}{\mu(1 - \rho)} = \mathbf{\frac{\rho^2}{1 - \rho}}
    $$

図7-4-1右のグラフが示す通り、平均遅延 $D$ は $\rho \to 1$ に向かって垂直な漸近線へ急上昇する **ホッケースティック曲線** を描きます。$\rho = 0.5$ なら遅延は処理時間の $2$ 倍で済みますが、$\rho = 0.8$ で $5$ 倍、$\rho = 0.9$ で $10$ 倍、$\rho = 0.99$ で $100$ 倍へ急増し、$\rho \ge 1$ では待ち行列が発散します。

#### (4) 複数窓口モデル $M/M/S$（待ち合わせ型）と統合効果

次に、同じ処理率 $\mu$ を持つ窓口（CPU コア、Web サーバ台数、回線チャネル）を **$S$ 個** 並べ、到着した客は 1 本の共通待ち行列に並んで空いた窓口へ入る $M/M/S$ モデルを考えます（安定条件は 1 窓口あたりの利用率 $\rho = \dfrac{\lambda}{S\mu} < 1$）。

$M/M/1$ との違いは、系内数 $n$ に応じてシステム全体の処理速度が変わる点です（図7-4-2左）。

* $n < S$ のとき：稼働中の窓口は $n$ 台だけなので、完了率は $n\mu$ になります。
* $n \ge S$ のとき：全 $S$ 台がフル稼働するため、完了率は $S\mu$ で頭打ちになります。

総トラヒック負荷を $a = \lambda / \mu$（$= S\rho$）とおくと、詳細釣り合い条件から定常確率は

$$
P_n = \begin{cases} \dfrac{a^n}{n!}\, P_0 & (0 \le n < S) \\[6pt] \dfrac{a^n}{S!\, S^{\,n-S}}\, P_0 & (n \ge S) \end{cases}
$$

となり、到着した客が「全 $S$ 窓口が塞がっていて待たされる確率」が有名な **アーランC式（Erlang C Formula）** $C(S, a) = \sum_{n=S}^{\infty} P_n$ です。$n \ge S$ の幾何級数部分の和を計算すると（途中の和の展開は省略します）、$M/M/S$ の平均待ち時間は簡潔に $W_q = \dfrac{C(S, a)}{S\mu(1 - \rho)}$ と表せます。

特に実験Bで比較した $S = 2$（$M/M/2$）では、$P_0 = \dfrac{1 - \rho}{1 + \rho}$、待ち確率 $C(2, 2\rho) = \dfrac{2\rho^2}{1 + \rho}$ と整理できます。ここで $1 - \rho^2 = (1 - \rho)(1 + \rho)$ と因数分解して独立 $M/M/1$ の平均待ち時間 $W_{q\,(M/M/1\text{独立})} = \dfrac{\rho}{\mu(1 - \rho)}$ をくくり出すと、

$$
W_{q\,(M/M/2)} = \frac{\rho^2}{\mu(1 - \rho^2)} = \frac{\rho^2}{\mu(1 - \rho)(1 + \rho)} = \underbrace{\frac{\rho}{1 + \rho}}_{\text{必ず } < 1} \cdot \frac{\rho}{\mu(1 - \rho)} = \frac{\rho}{1 + \rho} \cdot W_{q\,(M/M/1\text{独立})}
$$

となります（図7-4-2右）。たとえば $\rho = 0.5$ なら待ち時間は独立2本の **1/3**、$\rho = 0.8$ でも約 **44%** へ削減され、「資源を細かく分割するより、1つの大きなプール（共有キュー）へ統合する方が常に大きく短縮できる」ことが数学的に示されます。

#### (5) 即時式（損失系）$M/M/S/S$ とアーランB式・派生モデル

ここまでの $M/M/1$ と $M/M/S$ は「満員なら待合室で待つ（待ち合わせ系）」でした。一方、[6-1節](../6/6-1.md)の **回線交換網（電話交換局）** や、**同時接続数に上限 $S$ があり満員時は即座に `503 Service Unavailable`（あるいは話し中）を返して拒否するシステム** では、待合室（待ち行列）が 0 であり、系内最大収容数が窓口数 $S$ と等しい **$M/M/S/S$（即時式／損失系）** モデルになります（図7-4-3左）。

状態は $0, 1, \dots, S$ の有限個しか存在せず、状態 $S$（全回線使用中）で新たな呼（接続要求）が到着するとそのまま **呼損（ブロック／損失）** として捨てられます。

総トラヒック量（**呼量**）を **$a = \lambda / \mu$（単位：アーラン［Erlang, Erl］**。平均保留時間 $1/\mu$ あたりに到着する平均呼数）とおくと、状態 $0 \sim S$ の詳細釣り合い条件は $M/M/S$ の前半とまったく同じであり、

$$
P_n = \frac{a^n}{n!}\, P_0 \qquad (n = 0, 1, \dots, S)
$$

となります。全確率の和 $\sum_{k=0}^{S} P_k = 1$ より $P_0 = \left(\sum_{k=0}^{S} \dfrac{a^k}{k!}\right)^{-1}$ が定まるため、到着した呼が満員で拒否される確率（**呼損率：$B(S, a) = P_S$**）は次の **アーランB式（Erlang B Formula）** で厳密に与えられます。

$$
B(S, a) = P_S = \frac{\dfrac{a^S}{S!}}{\displaystyle\sum_{k=0}^{S} \frac{a^k}{k!}}
$$

具体例を手計算してみます。回線数 $S = 3$ 本の交換局へ、トラヒック量 $a = 2\text{ アーラン}$（例：1時間あたり平均 40 回の通話が到着し、平均通話時間が 3 分 $= 1/20$ 時間 $\implies a = 40 \times \frac{1}{20} = 2\text{ Erl}$）がかかるとき、

$$
B(3, 2) = \frac{2^3 / 3!}{1 + \dfrac{2^1}{1!} + \dfrac{2^2}{2!} + \dfrac{2^3}{3!}} = \frac{8/6}{1 + 2 + 2 + 8/6} = \frac{4/3}{19/3} = \frac{4}{19} \approx \mathbf{0.211} \quad (21.1\%)
$$

となります。つまり 3 本では約 21% の電話が話し中になりますが、もし回線を $S = 6$ 本へ増やすと $B(6, 2) = 4/331 \approx \mathbf{1.2\%}$ まで大きく下がります（図7-4-3右）。さらに、アーランB式は $M/G/S/S$（通話時間が指数分布でなく任意の一般分布 $G$ であっても）まったく同じ式が厳密に成り立つというロバスト性（**不感性：Insensitivity**）を持っています。

> **【コラム：アグナー・アーランと「なぜサーバ監視の CPU 利用率アラートは 70〜80% で鳴るのか」】**
>
> 待ち行列理論の創始者であるデンマークの数学者 **アグナー・クラルプ・アーラン（Agner Krarup Erlang）** は、1909年からコペンハーゲン電話会社で「何人のオペレータと何本の電話回線を用意すれば、客を待たせすぎず、かつ設備費を無駄にせずに済むか」という実務上の問いを解くために、ポアソン過程とアーランB式・アーランC式を生み出しました。
>
> それから100年以上経った現代のクラウド運用（**SRE**：Site Reliability Engineering）でも、Web サーバやデータベースの CPU 利用率アラートは「100% になったら鳴らす」のではなく、経験則として **70%〜80% で警告を鳴らす** ように設計されます。その数学的な根拠こそ、図7-4-1右の **$M/M/1$ のホッケースティック曲線** です。利用率が $70\%$ から $80\%$ へ上がるだけで遅延は $3.3$ 倍 $\to 5$ 倍へ増え、そこから利用率がさらに $15$ ポイント上昇（トラヒック量としては $+18.75\%$ 増）して $95\%$ になっただけで遅延は **20 倍** へ急上昇してしまうため、70〜80% の段階でオートスケール（$S$ の増設）を発動させる必要があります。

また、損失系の周辺には次の2つの重要な派生モデルがあります。

* **$M/M/1/1$（単一窓口の即時式）：** $S = 1$ の最小モデルであり、呼損率は $B(1, a) = \dfrac{a}{1 + a} = \dfrac{\lambda}{\lambda + \mu}$ となります（状態 `0` と `1` の2状態を行き来する構造は、下記の故障・修理モデルと同型です）。
* **エングセットモデル（Engset Model：有限呼源）：** アーランB式は「電話をかけてくるユーザ母集団が無限大」と仮定して到着率 $\lambda$ を一定とみなしますが、社内内線のようにユーザ総数 $M_{\text{src}}$ が有限（$S < M_{\text{src}} < \infty$）な場合は、すでに $n$ 人が通話中になると残りの空きユーザが $M_{\text{src}} - n$ 人へ減るため、到着率が $(M_{\text{src}} - n)\lambda_0$ へ低下します。この有限呼源の即時式を扱うのがエングセットモデルであり、同じ平均負荷でもアーランB式より呼損率が低くなります。

> **【コラム：待ち行列（$M/M/1/1$）と信頼性工学の稼働率（MTBF・MTTR）】**
>
> $M/M/1/1$ の 2 状態マルコフ連鎖（状態 `0`＝正常稼働、状態 `1`＝故障修理中）は、そのまま 1 台のサーバやディスク装置の故障・修理モデルへ当てはめることができます。単位時間あたりの故障率を $\lambda_{\text{fail}} = 1/\text{MTBF}$（MTBF：平均故障間隔）、修理率を $\mu_{\text{rep}} = 1/\text{MTTR}$（MTTR：平均修理時間）とおくと、詳細釣り合い条件 $\lambda_{\text{fail}} P_0 = \mu_{\text{rep}} P_1$ と $P_0 + P_1 = 1$ より、装置が正常に稼働している定常確率（**稼働率：Availability**）は次式で与えられます。
>
> $$
> A = P_0 = \frac{\mu_{\text{rep}}}{\lambda_{\text{fail}} + \mu_{\text{rep}}} = \frac{1/\text{MTTR}}{1/\text{MTBF} + 1/\text{MTTR}} = \frac{\text{MTBF}}{\text{MTBF} + \text{MTTR}}
> $$
>
> 故障を完全にゼロにする（$\text{MTBF} \to \infty$）ことが現実的に難しい大規模システムでは、監視・自動フェイルオーバによって **$\text{MTTR}$（復旧時間）を極力短くする** ことが、稼働率（例：$99.99\%$）を高めるうえで大きな効果を持ちます。

### 4. 限界と補正（Critique & Adaptation）

$M/M/1$ や $M/M/S$ は見通しのよい基本モデルですが、現実のインターネットやサーバシステムへ適用するときは、次の2つの限界と補正を押さえておく必要があります。

#### (1) 「指数分布・ポアソン到着」の前提が崩れる現実（$M/G/1$ の P-K 公式と自己相似性）

$M/M/1$ では到着がポアソン過程、処理時間が指数分布（変動係数 $C_s = 1$）に従うと仮定しています。しかし実際のシステムでは次の2つのズレが生じます。

1. **処理時間の重い裾（Heavy-tailed）分布と $M/G/1$ の P-K 公式：**
    実際の Web サーバやストレージでは、大半は数ミリ秒で終わる軽い処理なのに、ごく一部に数秒かかる巨大な検索クエリや動画転送が混ざるため、処理時間の分散 $\sigma^2$ が指数分布よりはるかに大きくなります。処理時間が任意の一般分布 $G$（平均 $1/\mu$、分散 $\sigma^2$、変動係数 $C_s = \sigma / (1/\mu) = \mu\sigma$）に従う $M/G/1$ モデルの平均待ち時間は、**Pollaczek-Khinchin（ポラチェック＝ヒンチン：P-K）公式** で与えられます。

    $$
    W_{q\,(M/G/1)} = \frac{\rho}{\mu(1 - \rho)} \cdot \frac{1 + C_s^2}{2}
    $$

    この式は実践的な教訓を示しています。

    * **処理時間が完全一定のとき（$M/D/1$：$C_s = 0$）：** 待ち時間は $M/M/1$（$C_s = 1$）の**ちょうど半分**に減ります。
    * **処理時間のばらつきが大きいとき（$C_s > 1$）：** たとえ平均処理時間 $1/\mu$ と利用率 $\rho$ がまったく同じでも、**変動係数の 2 乗 $C_s^2$ が大きいほど待ち時間が際限なく悪化**します（例：$C_s = 3$ なら $M/M/1$ の **5 倍**、$M/D/1$ の **10 倍** 待たされます）。

2. **バースト性トラヒックの自己相似性（Self-Similarity）：**
    現実のインターネットトラヒックは、ポアソン到着のように時間窓を広げれば平滑化されるのではなく、ミリ秒・秒・分・時間のどの時間スケールで観測しても似たような塊（バースト）が現れる **自己相似性** を示すことが知られています。そのため、同じ平均利用率 $\rho$ でもポアソン仮定の予測より長い待ち行列が発生しやすくなります。

**補正：** 実システムでは「平均処理時間」だけでなく**処理時間のばらつき（分散や、上位 1% の最も遅い応答を表す p99 テールレイテンシ）を抑えること**が重要です。巨大な重いジョブと短い軽いジョブを同じキューに混ぜず、[3-3節](../3/3-3.md)の MLFQ や専用ワーカープールへ分離（優先度付き待ち行列）してコンボイ効果を防ぎ、トラヒックのバーストには余裕を持った容量設計とシェーピング（流量平滑化）で備えます。

#### (2) 有限バッファ（$M/M/1/K$）とリトライストーム（再送の正のフィードバック）

現実のルータやサーバのメモリは有限なので、系内収容数（処理中＋待機中）には上限 $K$ があります（**$M/M/1/K$**）。状態数が $0 \sim K$ の有限個に限られるため $\rho \ge 1$ でも定常分布が存在し、詳細釣り合い $P_n = \rho^n P_0$ と有限等比級数の和 $\sum_{n=0}^{K}\rho^n = \dfrac{1 - \rho^{K+1}}{1 - \rho}$（$\rho \ne 1$）から、満杯時に新規パケットが廃棄・拒否される損失確率 $P_K$ は次式で与えられます（なお $\rho = 1$ のときは全状態が等確率となり $P_K = \dfrac{1}{K + 1}$ です）。

$$
P_K = \frac{(1 - \rho)\,\rho^K}{1 - \rho^{K+1}} \qquad (\rho \ne 1)
$$

キューが満杯になるとパケット廃棄やタイムアウトが起きますが、ここで深刻な障害を招くのが **リトライストーム（Retry Storm）** です。

サーバが混雑して応答が遅くなりタイムアウトが増えると、クライアント側が一斉に自動再送（リトライ）を始めます。すると再送リクエストが新たな到着率 $\lambda$ をさらに押し上げ、$\rho$ が $1$ を超えてシステムが復帰不能な飽和状態へ陥ります（[6-3節](../6/6-3.md)の ALOHA の輻輳不安定や [7-3節](7-3.md)の 1986 年輻輳崩壊と同型です）。

**補正：**

* **ルータ側：** バッファが 100% 満杯になる前に先制して確率的にパケット廃棄や ECN マーキング（[7-3節](7-3.md)）を行い、キューを浅く保つ **AQM（Active Queue Management：RED［Random Early Detection］/ CoDel［Controlled Delay］）** を導入します。
* **クライアント側：** タイムアウト時の自動リトライには必ず **指数バックオフ＋ジッタ（ランダムな揺らぎ）** と、異常時に一時的に要求を遮断する **サーキットブレーカ** を組み込みます。

> **【確認の問い】**
>
> 1. **（負荷 2 倍時のスケール設計：独立 $M/M/1 \times 2$ vs 共有キュー $M/M/2$ の定量比較）**
>     1 台あたりの平均処理率が $\mu = 100\text{ 件/秒}$（平均処理時間 $1/\mu = 10\text{ ms}$）の Web サーバについて、アクセス負荷が従来の $\lambda = 80\text{ 件/秒}$ から **2 倍の $\lambda = 160\text{ 件/秒}$** へ増えたため、同性能のサーバを **2 台** に増設しました（1 台あたりの利用率はどちらも $\rho = 0.8$ です）。
>
>     * (a) 2 台のサーバそれぞれに独立したキューを持たせて負荷を半分（各 $\lambda = 80\text{ 件/秒}$）ずつ振り分ける構成（独立 $M/M/1 \times 2$）における、**平均待ち時間 $W_q$** と **平均応答時間 $D$**［$\text{ms}$］を求めてください。
>     * (b) ロードバランサで 1 本の共通キューから空いたサーバへ振り分ける構成（共有キュー $M/M/2$）における、**平均待ち時間 $W_q$** と **平均応答時間 $D$**［$\text{ms}$］を求め、「平均待ち時間 $25\text{ ms}$ 以下（平均応答時間 $35\text{ ms}$ 以下）」という SLA 基準に照らして 2 構成を比較してください（小数第 1 位まで）。
>
> 2. **（アーラン B 式による最小回線数設計と P-K 公式による処理時間分散の影響）**
>     次の 2 つの問いに答えてください。
>
>     * (a) トラヒック量（呼量）が $a = 1\text{ アーラン}$ である即時式（$M/M/S/S$）の通話システムにおいて、**呼損率 $B(S, 1) \le 5\%$** を満たすために必要な最小回線数 $S$ を、$S = 3$ と $S = 4$ の呼損率をアーラン B 式で手計算して決定してください。
>     * (b) 同じ平均処理時間 $1/\mu$、同じ利用率 $\rho$ を持つ $M/G/1$ システムにおいて、処理時間が完全一定なサービス（$M/D/1$: $C_s = 0$）と、重いジョブが混在する高分散サービス（$C_s = 3$）とで、**平均待ち時間 $W_q$ の比** は何倍になるか P-K 公式から求め、システム設計上の教訓を 1 文で述べてください。

> 3. **（即時リトライによるリトライストームの機序と指数バックオフ＋ジッタの効果）**
>     ある API サーバが平常時は利用率 $\rho = \lambda / \mu = 0.7$ で安定稼働していましたが、一時的な負荷上昇で応答遅延がクライアントのタイムアウト値を超え始めました。このとき多数のクライアントが「タイムアウト直後に待たず即時一斉リトライ」を行う設定になっていると、なぜ負荷が自然に収まらず障害が悪化し続けるのでしょうか（**リトライストーム**）。$\rho = \lambda / \mu$ の変化の観点から機序を説明し、**指数バックオフ＋ジッタ** がなぜ有効なのかを答えてください。
